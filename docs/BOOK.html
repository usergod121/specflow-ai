0. 一句话与五站

给它一个项目 + 一句需求，它自己把五站跑完；每一站都有闸，上一站没冻结，下一站连点都点不动。

① 环境  →  ② 探针  →  ③ 用例  →  ④ 开发  →  ⑤ 测试
搭起来      摸家底      定验收线     改代码      容器里逐条验

五站的顺序与语义是写死的，这是本项目最值钱的性质：任何时候问「卡在哪一站、为什么卡」，都有唯一答案。

1. 核心认知（三层）

第一层：它是流水线，不是全能 Agent

Agent 只是流水线上那几站的「手」。站序、每站的产物、站与站之间的闸，都不由模型决定。 所以它不会「自己规划出一个新流程」——这既是限制，也是可解释性的来源。

第二层：闸是唯一判据，而且是纯函数

Facts（事实）是纯数据，Gate（闸）是 Facts → 一句话 的纯函数。 同一个 Facts 永远给同一个答案，于是闸能被单测钉死（14 条 GatesTest）， 界面上的「为什么还不能点」与 409 的正文是同一句话。

为什么要强调「纯」：上一版的判据散在路由里、在服务里、在页面里，三份真相。 最典型的一次——写事实的地方写 envConfirmed、读的地方读 envReady， 于是「起环境成功过」这件事闸从来没看见过，① 永远冻结不了。

第三层：状态是文件，事件是流水账

没有数据库。一条流程一个目录：.specflow/flow/<id>/，里面是 flow.json（五格状态+产物）、events.jsonl（统一归档日志）、 cases.json、probe.json、summary.md、snapshot/、runs/。 人能直接打开看——排错时这一条比什么都值钱。

// 三条铁律（core/EventLog.java 的类注释）
1. 只有一个写者：日志、工具调用、闸、收场，全从 append() 出去
2. id 恒等于行号：追加前现读行数、盖号、写一行 —— 于是「游标」与「第几条」是同一个数
3. 不缓存：读一律回盘上读 —— 内存里再存一份就又多了一个真相

2. 顶层抽象

抽象类职责不许做什么
事实flow.Facts闸的输入：编译命令、环境起过没、容器能构建没、用例几条…不读盘、不判闸
闸flow.Gates唯一判据：空串=能做，否则是给用户看的那句话不读盘、不看时间
状态flow.FlowState五格 LOCKED/READY/DONE + 每格产物不判能不能动
落盘flow.Store / core.Atomic原子读写（临时文件 + ATOMIC_MOVE）不解释业务
事件core.EventLog单写者日志，id ≡ 行号，重启接着数不缓存
过程core.Progress长任务的唯一过程口（step/line/warn/fail/done）不各自写文件
工具agent.Tool + ToolRegistry名字+说明+参数声明+执行体；失败是结果不是异常不碰允许根之外
循环agent.LoopReAct：模型 → 工具 → 结果回喂；有轮次/工具数上限不判业务闸
裁决test.CaseList + CaseBudget用例的终态与证据；每条用例的轮次预算不自己造用例
五条不变式（违反任何一条都会重新引入旧版本踩过的坑）：
① 事件只有一个写者 ② Event.id 恒等于行号 ③ 一个事实只有一个名字（Facts 里的常量） ④ Layout 是唯一的路径权威 ⑤ 长任务只从 Progress 一个口说话。

  │
  ├─ Runs 开工：Journal.BEGIN（runs/<runId>.jsonl）+ Jobs 登记（可叫停）
  │    │
  │    ├─ TestSandbox：项目复制一份到 flow/<id>/sandbox/<runId>，
  │    │   渲染 compose（挂副本，不挂真项目），up -d --wait
  │    │
  │    ├─ Preflight（便宜的一问）：容器里 command -v <构建工具>
  │    │   缺 → 立刻失败，指名「改 env.yaml 的 image 或 init」
  │    │
  │    ├─ TestAgent（ReAct）：
  │    │    ├─ 工具链 = 预算（每用例 12 轮）→ 提权/装工具链拦截 → 审批 → 冻结

5. 逐包逐类

5.1 core —— 地基（谁都不许绕）

Layout：项目里每一样东西落在哪，只有这一处定义。

public record Layout(Path root) {           // 构造时归一化成绝对路径
    public Path flowJson(String id)  { return flow(id).resolve("flow.json"); }
    public Path events(String id)    { return flow(id).resolve("events.jsonl"); }
    public Path cases(String id)     { return flow(id).resolve("cases.json"); }
    public String show(Path file)    { ... }   // 展示路径永远是正斜杠
}

为什么必须是一个类：落点是跨模块约定（写的人、读的人、清理的人、界面显示路径的人）。 四处各拼一遍字符串的结果是「有一处少了一层目录」，而那种错只在真跑起来时现形。

EventLog：统一归档日志，一行一条事件。

public synchronized Event append(Event event) {
    Event stamped = event.withId(lines() + 1);     // ① 现读行数 ② 盖号 ③ 写一行
    Atomic.appendLine(file, Json.line(stamped));
    return stamped;
}

一句话解释：游标 = 行号。界面拿 ?from=120 就是"第 121 行起"，断线重连不用补偿； 进程重启也接着数（上一版每次从 1 起，重启后界面历史全没了）。

Progress：长任务的唯一过程口。实现只有一个 EventProgress—— 它把过程写成事件，界面读的就是那份事件流。上一版有两条通道，结果进度写进 A、界面读 B， 用户原话是「我只听到电脑风扇一直转」。

5.2 flow —— 流程（判据与状态的唯一住处）

Facts：11 个字段的全是闸要问的问题，每个字段名只在 Facts 里出现一次。

public record Facts(String compile, boolean envReady, boolean envNotNeeded, boolean envDeclared,
                    boolean probeFiles, boolean probePrompt, int caseCount, int casePending,
                    boolean testRun, boolean submitted, boolean compilePassed,
                    boolean containerBuild, String containerDetail) { ... }

最后两个字段是 v3 加的：containerBuild = 「容器里真构建过」。 它和 compilePassed（宿主机编译过）是两件事——见第 6 节的「两条编译」。

Gates：五个门槛 + 一条硬规则。硬规则是顺序：上一格不是 DONE， 下一格的动作一律拒，而且话里要点名差哪一步。

public static String blocked(Node node, Facts facts, Map<Node, State> states) {
    Node previous = node.previous();
    if (previous != null && states != null && states.getOrDefault(previous, State.LOCKED) != State.DONE) {
        return "上一步「" + previous.title() + "」" + word(was) + "：先把…做完并冻结…";
    }
    return blocked(node, facts);            // 再看这一格自己的门槛
}

FlowService：五格的动作都在这里，路由只做参数翻译。它有两个「闸入口」：

requireOpen(node, action)      // 完整闸：动作进来之前（前置没 DONE 一律 409）
requireReachable(node, action) // 只判前置：给「这一格的活正是为了满足它自己的门槛」用
requireReachable 为什么非有不可：① 的门槛是「编译命令非空 + 环境起过」， 而「探测环境」正是产出编译命令的那一步。按完整闸判，用户第一次进来连点都点不了——自锁。 这是端到端实跑撞出来的（409 环境还没起来），不是想出来的。

5.3 env —— 环境（起容器、编译、验能力）

类干什么关键设计
EnvConfigLoader读 env.yaml，结构问题带行号一次报全只做结构校验；「这条命令危不危险」不在这一层
Compose按 env.yaml 渲染 composeapp：uid 1000 + cap_drop ALL + 限额 + 只挂项目树 + 一个 external 缓存卷
Environmentup / reset / down / status；inApp() 在容器里跑命令init 命令走 sh -s 的 stdin（Windows 上 argv 会吃引号）
Compiler跑项目配的编译命令在宿主机上跑（"这台机器怎么构建这个项目"），且过 CommandGuard
Capabilities起完环境：认工具 → command -v → 真跑一次构建v3 新增：把「能用」变成可执行
Budgets「这一步我愿意等多久」的唯一换算处v3 新增：修掉「旋钮改了没反应」

5.4 agent —— ReAct 与工具

Loop：状态机 + 有状态记忆（模型每轮看到完整历史），两种出口：交差（submit）或撞上限。

loop.run(system, message)
  └─ 每一轮：模型回一段文本 → 协议解析 → 若是工具调用：registry.call() → 结果回喂
                       └─ 解析不出（模型说了废话）：用更直白的 retryNotice 重试，两次还是不行才收场

工具集（少而专，每个工具的错误都写给模型看）：

工具作用边界
read_list / read_file看目录 / 读文件Roots：拒绝对路径、拒绝 ..、拒软链逃逸、密钥文件一律不给
write_file / apply_patch整篇写 / 锚点替换⑤ 里被 Frozen 包住，验收阶段改 src/ 会被拒
bash在容器里跑一条命令三条拦截：forbidden（挂宿主/借网络栈/写块设备）、privilege（sudo 直接拒）、bootstrap（装工具链直接拒）
case_update写回一条用例的终态 + 证据只能写清单里已有的编号

5.5 test —— 容器里逐条验

TestSandbox：把项目复制到 flow/<id>/sandbox/<runId>， 渲染一份挂副本的 compose 并起容器。真项目一个字节都不碰——这是这一格的边界。

CaseBudget（v3 新增）：每条用例的轮次预算。

当前用例 = 清单里第一条还没到终态的用例      // 笨，但账和人一眼能看懂的账是同一本
每次工具调用 → 记在当前这一条头上
超了预算 → 那一条标 SKIPPED（带原因）→ 注意力推到下一条

Preflight（v3 新增）：开工前 command -v <tool>，缺了就立刻失败并指名 ①。 这一条是这场重构里最划算的改动：几百毫秒，替掉了一次 28 轮 / 15 分钟的自救。

CaseList：用例的状态机 PENDING → PASS/FAIL/ERROR/SKIPPED， 提交时五条机器判据（非空、无 PENDING、PASS 有证据、非 PASS 有原因、至少一条真结论）。

5.6 web —— 路由与装配

Api 只做三件事：取参数、调下层、拼响应。判据一条都不在这一层—— 路由里出现 if (state == …) 就说明判据漏上来了。另有两件：

  • TraceFilter：每个请求一个 req id，→ / ← 各一行带状态与耗时（跳过静态资源）；
  • Errors：把各类异常翻成 {"error":"一句话"}；静态资源缺失是 404 且不刷 ERROR 日志。

6. 工程细节与取舍

6.1 两条编译（这是 v3 的核心修复）

宿主 Compiler容器 Capabilities
问的问题这台机器能不能构建这个项目下游真要用的时候能不能用
谁需要它④ 每次交差的快速反馈① 的闸（能不能冻结）
产出事实compilePassedcontainerBuild
为什么要两条：用户的真项目 env.yaml 写的是 eclipse-temurin:17-jdk ——只有 JDK，没有 Maven。① 在宿主机上编译（宿主装了 Maven）→ 绿灯； ⑤ 进容器 mvn 找不到 → 自己下载安装 Maven，烧掉 60 轮里的 28 轮，一条用例都没验成。 现在 ① 会因 containerBuild=false 直接拒绝冻结，并把「改 image 或 init」写在话里。

6.2 依赖缓存跨轮、数据每轮重置

compose 给 app 挂一个 external 命名卷到 /specflow-home： down -v 不删它（Maven 的 ~/.m2 跨轮复用），而项目树每轮是新副本。

volumes:
  "sf-<项目>-<指纹>-home":
    external: true          # ← 不属于这次 up/down 的生命周期
    name: "sf-<项目>-<指纹>-home"

6.3 三层预算

层上限超了怎么办对应事故
整轮max(60, 用例数×12+20) 轮失败收场，但如实报已写下几条结论60 轮 0 结论 + 摘要谎报 0 条
每条用例12 轮工具调用标 SKIPPED，推进下一条；可「重试这一条」一条用例吃掉整轮
单条命令Budgets（默认 30 分钟，可改）超时终止并说清「容器里那半截可能还在跑」写死 300 秒把长构建掐死两次

6.4 守卫三档（CommandGuard）

档判据处置
一律拒--privileged、docker.sock、-v /:/host、--net host、写块设备直接失败，不问（问「要不要允许把 C: 挂进来」本身就是坏问题）
停下来问dd、curl … | sh、chmod 777、成片删y/n 面板；被拒时返回模型能继续的失败结果
v3 新增两档sudo → 直接拒（容器里不可能成功）；装工具链 → 直接拒并指名改 env.yaml见 CommandGuard.privilege / .bootstrap

6.5 SSE 而不是轮询

GET /api/node/{key}/stream?from=N          → text/event-stream
event: events  data: {"events":[…],"next":121,"running":true,"stage":"…"}
event: ping    data: {"at":"12:34:56"}      # 15 秒一次，闲时保活
event: done    data: {…}                    # 没有在跑的活了 → 推完主动关

三条设计决定：① 载荷与 ?from= 完全同形（游标语义不变，客户端零补偿逻辑）； ② 没有在跑的活就主动关（不关的话 EventSource 会自动重连，界面会永远"显示成在跑"）； ③ 前端连不上三次自动退回轮询（不让界面假装还连着）。

7. v3 这一轮改了什么

改动解决的事故怎么验
① 的闸加 containerBuild，起完环境在容器里真构建一次宿主机有 Maven、容器里没有，① 却绿灯GatesTest 3 条新钉子 + 真项目会红
TestAgent.withContainerRoot：提示词同时给出宿主与容器两个路径模型在 bash 里猜路径，5 轮白烧提示词断言
CaseBudget：每用例 12 轮 + SKIPPED 终态 + 单条重试60 轮用尽 12 条用例 0 结论CaseBudgetTest 5 条
Preflight：⑤ 开工前 command -v28 轮 / 15 分钟的自救缺工具时立刻失败并指名 ①
CommandGuard：放行 $HOME、sudo 直接拒、新增装工具链拦截2 轮无理由硬拒 + 187 秒无效审批 + 20 轮装 MavenCommandGuardTest 6 条
Budgets：超时收成一个来源界面「改超时」只回显不生效BudgetsTest 4 条 + Select-String 查硬编码
依赖缓存卷（external）每轮重下依赖（17 分钟 / 7 轮 sleep）ComposeTest 断言 external: true 与 HOME
SSE + 单条重试入口1.2 秒轮询慢半拍；被跳过的用例无法单独重跑curl 看 event: events；105 条前端测试
① 与 ④ 补「冻结」按钮 + wiring.spec.js页面没有冻结入口，下游永远解锁不了前端 10 条接线钉子

8. 明确没做的（不许当成做了）

  • .specflow/flow.yaml（流程 DSL）没做：评审判断它会是「第四份真相」，且时间不够。 这一轮的"统一封装"落在 Facts/Gates/CaseList 三处既有抽象上，没有新造一层。
  • 上下文压缩（compact）没做：长对话仍可能爆。Loop 有轮次上限兜底，但没有摘要。
  • 可恢复中断没做：审批仍是"阻塞线程 + 10 分钟超时按拒"。v3 只是把 sudo 从审批里拿掉了 （那是 187 秒的真正来源）。
  • 运行级 checkpoint / 崩溃后接着跑没做：仍然只有「没写 END = 中断」+ 快照回滚。
  • 工具中间件链（ToolHook）没做：仍然是装饰器（Frozen/CaseBudget 各包一层）。
  • 跨流程查询、事件流 O(n) 优化没做：EventLog.append 仍是全量读行数。
