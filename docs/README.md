# 文档地图

代码是唯一的真相，文档都会过期。看文档时记着这一点：数字对不上代码，就是文档旧了，改代码的那次没回来改文档。

## 按目的挑

| 我想…… | 看这份 |
| --- | --- |
| 先搞懂这东西是干嘛的、跑一遍 | 仓库根的 `README.md` |
| 改代码前，先知道哪些东西不许动 | `ARCHITECTURE.md`（十二条不变量） |
| 弄明白为什么这么设计、某个类具体在干什么 | `SYSTEM.html`，用浏览器打开 |
| 调接口、接前端 | `API.md` |
| 改页面、加组件 | `UI.md` + 仓库根的 `DESIGN.md` |
| 判断某个功能到底做了没有 | `DELIVERY.md` |
| 提改动 | 仓库根的 `CONTRIBUTING.md` |

## 按顺序读

第一次接触这个项目，按这个顺序读，每读一份回答一个问题：

1. `README.md` —— 它分几步、每步产出什么文件。
2. `ARCHITECTURE.md` 的第 1 到第 4 节 —— 目录怎么放、十二条不变量是什么。
3. `API.md` 的 `/api/flow` 那一节 —— 界面拿到的五格视图长什么样。看懂了这一节，界面和引擎的边界就清楚了。
4. `SYSTEM.html` 的 §1.0（五遍读法）、§2.5（八个概念）、§5（关键机制）—— 为什么这么写。
5. 再回头读代码。从 `core/EventLog`、`flow/Gates`、`agent/Loop` 这三处开始，够用了。

`SYSTEM.html` 里有逐包逐类的表和源码片段，要动某个包之前，先找到那一节读完。

## 怎么验文档没骗你

- 文档里写着「14 个类」「231 条测试」「40 条路由」这类数字，都是能数的。数一遍，对不上就是旧了。
- 文档里贴的源码片段是从代码里抄的。抄的这份要是和你读到的不一样，以代码为准，然后回来把文档改掉。
- `SYSTEM.html` 里每个 `div.why` 是一段事故记录。照着它说的去代码里找那段处理，找不到就说明有人把修复删了。

## 各文档的维护点

| 文件 | 什么时候必须回来改 |
| --- | --- |
| `README.md` | 依赖、命令行、构建方式、已知限制变了 |
| `ARCHITECTURE.md` | 加或改不变量、改目录落点、改事件协议、改工具列表 |
| `API.md` | 加或改路由、状态码、错误正文 |
| `UI.md` / `DESIGN.md` | 页面结构、状态词、色板、间距变了 |
| `SYSTEM.html` | 上面几份改了之后，它里面引用的数字和源码片段也要跟着改 |
| `DELIVERY.md` | 交付前追加一轮：验了什么、结论、没做什么 |

## 落点速查

配置和运行时数据都在项目目录里，`~/.specflow/` 放全局的东西：

```
<项目>/.specflow/      project.yaml  local.env  env.yaml  flow/<id>/…
~/.specflow/           logs/engine.log  recent.json  projects.json
```

细节见 `ARCHITECTURE.md` 第 3 节。
