# specflow v2 · 架构与不变量

> **这份文档是唯一事实来源。** 代码怎么组织、名字怎么起、哪条判据归谁，一律以这里为准。
> 与代码不一致时：先改代码，再改这里；**不许只在脑子里对齐**（上一版就是这么烂掉的）。
> 面向读者：写代码的人、review 的人、以及任何"不记得上一轮发生了什么"的人。

## 1. 一句话

把「改一个项目」拆成五步，每一步的产出都落在**项目目录里的文件**上，
每一步做完都要**人点头**才往下走，中途出错能退回上一步，任何时候崩了都能恢复。

## 2. 技术栈（不变）

| 层 | 选型 | 版本 | 为什么 |
|---|---|---|---|
| 后端 | Java + Maven | 17 | 上一版就是它，环境已就绪 |
| 后端框架 | Spring Boot（内嵌 Tomcat） | 3.3.x | 只当 HTTP 与 JSON 层用，不引 JPA/Spring Security |
| 模型 | LangChain4j 的 OpenAI 兼容客户端 | 1.x | 用户可换 base-url，只要能讲 OpenAI 协议 |
| 容器 | Docker + `docker compose` | 本机 29.x | 测试只跑在容器里，宿主一个字节都不许沾 |
| 前端 | Vue 3 + Vite | 3.5 / 8.x | 不引组件库、不引 Tailwind：样式全在手写的 CSS 变量里 |
| 存储 | **项目目录下的文件** | — | 不引数据库。所有状态都是人能打开看的文件 |

**不引的东西**（引了就是上一版那种烂摊子）：JPA、Flyway、Redis、消息队列、
前端组件库、状态管理库（Pinia 也不要，一个 `reactive` 的 store 就够）、ORM。

```
specflow-v2/

  src/main/java/com/specflow/

    core/                      # 与业务无关的底子：原子写、工具、事件日志、快照
    flow/                      # 五节点、闸、状态机、回退
    env/                       # 环境：compose 渲染、起/停/取消、init/reset
    agent/                     # ReAct 循环、工具注册表、两个 Agent（探针 / 开发）
    test/                      # 测试 Agent：容器沙箱、用例清单、验收
    web/                       # 路由（薄，只做参数与错误翻译）
  src/main/frontend/           # Vue 3 + Vite
  src/test/java/               # 单元 + web 级
  docs/                        # 你正在看的三份
  fixture/                     # 端到端的目标项目（纯 Java、零依赖，含一个真 bug）
```

**项目里（被测项目）的落点**——只有这一份定义，代码里叫 `Layout`：

```
<项目>/.specflow/
  project.yaml            # build.compile、llm 配置（模型、base-url、api-key-env）
  local.env               # 密钥（永不回显、永不进副本、永不进日志）
  env.yaml                # ① 的声明：image / dependencies / env / init / reset
  flow/
    current               # 当前流程 id（一行）
    <flowId>/
      flow.json           # 五节点状态 + 每一步的产物（facts）
      events.jsonl        # 统一归档日志：一行一条事件，**行号 = 事件 id**
      cases.json          # ③ 的用例清单
      probe.json          # ② 的产物
      summary.md          # ⑤ 提交的那段总结（回喂 ④）
      snapshot/           # 写前快照（回滚用）
      runs/<runId>.jsonl  # 一次运行的逐轮留档（工具调用、模型调用）
      env/<时间戳>/compose.yaml   # 引擎渲染出来的 compose（不碰用户自己的）
      env/<时间戳>/compose.log    # up/init 的原始输出
```

## 4. 十二条不变量（每一条都是真踩过的坑）

违反其中任何一条，都算这一版失败。**写代码时先看这一节。**

1. **一个写者**。`events.jsonl` 只有一处追加（`EventLog`），它同时拥有事件 id：
   **id 恒等于行号**，进程重启后从文件行数接着数。
   *上一版：两个类各写一个文件、各数一套 id，界面按 `?from=` 拉取时重复/跳过、重启后历史整个消失。*

2. **一个事实只有一个名字**。跨模块传的事实（`envReady`、`compilePassed`…）写成
   `public static final String` 常量，写它的与读它的都用那一个常量。
   *上一版：写 `envConfirmed`、读 `envReady`，于是"起环境成功过"这件事闸从来没看见过，① 永远冻结不了。*

3. **产物只写一次落点**。`Layout` 一个类回答"某个东西落在哪"，别处不许拼路径。
   *上一版：同一个文件在四个地方各拼一遍，落点漂移只有线上才看得出来。*

4. **长任务只有一个出口**。起环境 / 编译 / 跑 Agent：过程事件走同一个 `EventLog`
   （同一个接口 `Progress`），不许"自己写一个日志文件，回头再同步"。
   *上一版：起环境的进度只写自己的文件，界面读的是另一条流 → 界面上什么都没有。*

5. **闸只有一处判据**。路由与界面都不许自己推闸：`Gates.blocked(node, facts[, states])` 是唯一来源
   （`Gate` 是"一格一个实现"的接口，`Gates.TABLE` 是那张表），界面只读它的结论（`blockedReason`）。
   前端**一行判闸逻辑都不许有**。

6. **写项目之前先拍快照，写文件一律原子**。`Atomic.write`（临时文件 + rename）与
   `Snapshot.capture/hold/rollback` 是仅有的两个写口。
   *上一版：有的地方裸 `Files.write`，断电/崩溃之后半份文件。*

7. **崩溃可恢复**。任何一次运行开工先写 `BEGIN`、收场写 `END`；启动时扫一遍没有 `END`
   的运行，按"中断"收场（回滚 + 补 END）并如实报给用户。

8. **模型与命令都只从一处出去**。模型只有 `Llm` 一个口；命令只有 `Shell`（容器内）与
   `Host`（宿主，仅编译）两个口，两个口都带超时、输出上限、逐行回调。
   **模型写的命令永远只在容器里跑**，非 root、`cap_drop ALL`。

9. **文案预算**。界面上任何一句解释性文字 ≤ 6 个汉字；长解释进 `title`（悬停才出现）。
   状态名固定几档：`未开始 / 进行中 / 已完成 / 失败`，不许自由发挥。

10. **归档日志统一且最新在上**。事件只有四种 `type`：`log` / `tool` / `result` / `gate`；
    界面渲染时**倒序**（最新一条在最上面），工具调用渲染成 chip（同 `callId` 两条合一枚）。

**补记（2026-10-17）**：上面十条管的是"别写错逻辑"，但实际捞出来的三个 bug **都不是逻辑错，
而是接线错**——② 的 `files`/`context` 没进 ④、`probe/save` 把字符串形态的 `context` 清成空、
`project.yaml` 只在打开项目那一刻读一次。它们零报错、全绿测试都抓不到，共同形状是
**"用户改过的东西，下一处没去读"**。所以再加一条口径：

> **11. 改完必须读得回来。** 凡是"人能在界面上改"的东西，它落在盘上之后，
> 下一处必须**现读**（`(size, mtime)` 没变复用缓存，变了整份重读），不许用"进程启动那一刻的快照"。
> 判据是"改盘 → 立刻问 → 必须是新值"，不是"我觉得它读的是新的"。

> **12. 一个功能"做完了"的标志不是它能跑，是它的输入有人给、输出有人用。**
> 只有测试在用的口子 = 生产没接（`Metrics` 曾零调用点）；只有一个调用者的钩子 = 接线没接完
> （`Loop.anchors` 曾只有 ⑤ 用）。新加一个"可配/可注入"的口子时，**必须同时说清谁给它输入**，
> 否则就写死默认值，别装成可配。

细节与七处修法见 `SYSTEM.html` §9 与 `docs/v3/DECISIONS.md` 第五·补 / 五·补二 / 五·补三节。

## 5. 五节点与闸

| # | key | 干什么 | 完成的判据（= 冻结条件） |
|---|---|---|---|
| ① | `env` | 环境 Agent 读项目 → 写 `env.yaml` 与编译命令；人可改；「起环境」拉镜像 + init；「编译」单独一步 | 编译命令非空 **且**（环境起过 **或** 声明不需要环境） |
| ② | `probe` | 需求（必填）+ 设计（可选）→ 探针 Agent 只读项目 → **四样产物**：可读文件 `files`、要改的文件 `changes`、几段「为什么相关」`context`、给开发的 `prompt`；四样都能手改，四样都进 ④ | 有可读文件 **且** prompt 非空 |
| ③ | `cases` | 用例 Agent 读需求/上下文 → 带标签的用例；人可增删改；冻结即锁定 | ≥1 条用例 **且** 每条都有描述与标签 |
| ④ | `dev` | 开发 Agent 在白名单内改真项目，每次 submit 编译一次，编译错误自动回喂 | 编译通过 |
| ⑤ | `test` | 测试 Agent 在容器副本里按清单逐条验，结论与证据写回清单；提交要附总结 | 清单无 PENDING **且** 已提交 |

**硬规则**：节点 N 不是 `已完成` → N+1 的动作一律 409 + 一句人话。
**回退即作废**：回到第 N 步，N 之后的一切（状态、产物、事件）全部作废并如实列出作废了什么。
**优化不是第六个节点**：它是 ⑤ 上的一个按钮（把 ⑤ 的总结当目标回喂 ④，③ 不再生成）。

## 6. 一次运行的形状

```
POST /api/node/<key>/<action>      → 202 {runId, cursor}（立刻返回，不阻塞）
GET  /api/node/<key>/events?from=  → {running, stage, events[], next}
POST /api/node/cancel              → 叫停正在跑的那一段（长任务真杀进程树）
```

- 长任务在后台线程跑，过程边走边追加事件（**这就是流式 chip 的来源**）；
- 界面按 `from=` 增量拉，只画新的；
- 任何一段收场都往事件流写一条 `type=result` 的载荷——**界面画那一页就只有这一个来源**；
- 动作被闸拦下时写一条 `type=gate` 的事件（事后翻得到"当时为什么不让点"）。

## 7. 工具（ReAct 的地基）

一个 `Tool` = 名字 + 参数 schema + 执行体。注册表按名字派发，**不抛异常**：
名字不认、参数不合法、内部炸了，一律翻成一份 `ok=false` 的结果喂回模型。

| 工具 | 谁用 | 说明 |
|---|---|---|
| `read_list` | 探针 / 开发 / 测试 | 列目录 |
| `read_file` | 全部 | 读文件（带行号、截断） |
| `apply_patch` | 开发 | 搜索替换式改文件，**只许改白名单里的** |
| `bash` | 测试 | 只在容器里跑，带超时与输出上限 |
| `submit` | 开发 / 测试 | 交差：开发=改完了，测试=这一条验完了 |
| `phase` | 测试 | 切换「准备 / 验收」阶段（验收期 `src/` 冻结） |
| `case_update` | 测试 | 写回一条用例的结论 + 证据 |

**执行前**推一条 `tool` 事件（`status=running`），**执行后**再推一条（`status=ok|error` + 耗时 + 全文），
两条共用 `callId`。这就是「一边跑一边冒」的 chip。
**高危命令**（提权 / 动设备 / `curl|sh` / 挂宿主）：停下来问用户 y/n，没人回答就按拒处理。

## 8. 与上一版的差别（砍掉了什么）

砍：老 `.specflow` 数据迁移、旧接口兼容层（`/api/drafts` `/api/tasks` `/api/chain`）、
按阶段配模型、模板库与上下文库面板、`TaskDraft` 这一层中间概念、双写日志、六节点遗留。
留：五节点语义、闸、回退作废、快照回滚、崩溃恢复、容器沙箱、流式 chip。

**新增且一开始就设计进去的**（上一版是事后打补丁）：`callId` 两段式工具事件、
事件 id = 行号、编译结论落档、`service:` 让命令去依赖容器里跑、`stdin` 把项目里的文件喂进容器命令。
