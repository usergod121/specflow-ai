## 五·补、用户一句话问出来的三类「我改了它没反应」

用户问的原话是：「我记得怎么好像是不是没有 text 文本替换了，用户只能直接修改 prompt？」
他不是在提需求，是在**描述一个他踩到的现象**。顺着这句话查下去，同一个形状有三条，
而且**全部零报错、全绿测试都抓不到**——它们的共同点是：东西都在，中间某一段没接上。

| # | 断在哪 | 用户看到什么 | 修法 | 判据 |
|---|---|---|---|---|
| 1 | ② 的 `files`/`context` **只存不用**：`Dev.run(prompt, whitelist, feedback)` 只吃三样，另外两样写进 `probe.json` 就没人再读 | 在 ② 改「上下文」，④ 一点反应都没有；想让它生效只能去改那段 prompt | `Dev.run(...)` 加五参数重载，`userMessage` 按「要做的事 → 先读哪儿 → 为什么相关 → 反馈」四段拼 | `DevMessageTest` 4 条直接钉提示词原文 |
| 2 | 前端把 `context` 当**一段多行文本**提交，后端 `Api.lines` 只认 `List` | 保存看着成功，刷新之后「上下文」是空的（被静默清成 `[]`） | `lines(Object)` 两种形状都认：`String` 按行拆、`List` 逐项 | `ApiTest` 用 String 存一次再读回来断言 |
| 3 | `project.yaml` 只在 `Project.open` 那一刻读一次（`raw` 是 final） | 填了编译命令 → 点冻结 → 闸说"编译命令还是空的"；界面上**没有"重开项目"这个按钮** | `Project.raw()` 按 `(size, mtime)` 每次问盘（与 `EventLog` 同一套口径：盘是真相，内存只是缓存） | `ProjectTest` 3 条：改盘 → 立刻读 → 必须是新值 |

**为什么这三条值得单独记一笔**：它们都不是逻辑错，而是**接线错**。
逻辑错会红、会抛、会在日志里留痕；接线错什么都不留，只有"人去点一下"才发现。
所以判据也换了形状：**不看实现，看"改完之后读回来是不是新的"**。

## 五·补二、一次端到端逼出来的第四条：编译命令要"两处都能跑"

| 现象 | 根因 | 修法 |
|---|---|---|
| ① 起完环境，`Capabilities` 在容器里构建**退出码 2**，① 冻结被闸拦下；而错误信息读起来像"环境坏了"（`GatesTest` 里那句「容器里有 `javac`，但构建没过」） | ① 的 Agent 交出 `javac -d out\main src\main\java\com\demo\*.java`——**Windows 写法**。宿主机（cmd.exe）认，Linux 容器里 `\` 是转义字符，`out\main` 变成 `outmain`。而 `EnvAgent.hostFacts()` 的**示例本身就是反斜杠**，等于在教模型写错 | ① 提示词改成「路径一律正斜杠，cmd.exe 也认」（治本）；② `Capabilities.verify` 在第一次构建失败且命令里带 `\` 时，按 Linux 写法再试一次，过了就**写回 project.yaml**（治标，代价一次构建） |

**这一条对判断"值不值得修"有用**：同一条编译命令**在两个地方跑**（④ 每次交差在宿主机、
① 的能力校验在容器），所以它不是"一条命令"，是"一条要在两个 shell 里都成立的命令"。
把它当成一条命令写，就会漏掉一半的约束——而漏掉的那一半，恰好是闸要拿来做判据的那一半。

## 五·补三、交付前那次系统核查：又抓到四条同形状的

用户要求「核查确保 100% 交付」。这次核查的判据换了：**不看"跑通没跑通"，只问"每一处接了吗"**。
用两条 grep 就能发现全部四条：<b>这个公开方法的调用点有几个？这个类的输入/输出有没有人消费？</b>

| # | 缺口 | 一句话 | 修法 |
|---|---|---|---|
| 1 | `Loop.anchors(...)` **只有 1 个调用点**（⑤） | 压缩的锚点表 ②③④ 一句都没有，一压缩就只剩"system + 任务书 + 尾巴" | 把「动过的路径 / 最近的失败」搬进 `Loop` 自己攒（`remember` + `anchorTable`），调用方只补"进度" |
| 2 | `Compact` 压**第二次**时把任务书扔掉 | 它假设 `messages.get(1)` 永远是任务书——第一次压完，第 1 条已经变成自己插的锚点了，于是第二次把锚点表当任务书抄下来、真正的需求被扔掉，锚点还叠成两份 | 改为"认头"：system + **第一条不是自己插的** user 消息 = 任务书；自己上次插的两条丢掉；对尾巴去重。**幂等** |
| 3 | `Snapshot`（把真项目退回原文）**零测试**，`accept()` **零调用点** | 回滚是唯一会反向写用户真项目的动作，写坏就是二次伤害；而每次开发都留一份没人处置的副本 | 补 6 条测试（逐字节回来 / 新建的删掉 / 清单没了不猜 / 不许处置两次 / 项目外的不拍但要说 / `latest()`）；④ 冻结时 `accept()` |
| 4 | `Metrics` 写完**一个调用点都没有**；`StuckCheck` 只包了 ⑤ | actuator 里永远只有框架指标；④ 反复读同一个文件照样烧光轮次 | `App` 装上 registry + 5 处调用（跑 / 收场 / 模型 / 审批 / 闸）；`StuckCheck` 五格都包（话术按「用例 / 这一轮」分） |
| 5 | `Loop.onToolResult`（+`INJECT`）**只有测试在用** | 一个"能换掉注入内容"的口子，生产代码没人接 —— 按自己刚写下的判据，它该被删 | 删掉，连同那 2 条测试（`LoopTest` 13 → 11）；需要它的那天再连调用方一起加 |

**为什么这四条值一笔**：它们和前面那三条（②→④ 断链、`context` 被清空、`project.yaml` 只读一次）
是**同一个形状**——东西都在、不报错、测试全绿，只是中间某一段没接上。
七条里<b>有五条</b>是"数调用点"就能发现的，所以判据写成一句可执行的话：

> **一个功能"做完了"的标志不是它能跑，是它的输入有人给、输出有人用。**
> 只有测试在用的口子 = 生产没接；一个调用者的钩子 = 接线没接完。

顺带记两条工程事故：**`mvn package` 因 jar 被占没更新，随后一轮冒烟 + 端到端全过，
验的是旧包**（靠 jar 时间戳才发现）；**`.ps1` 不带 BOM 时 PowerShell 5.1 按 ANSI 读，
中文注释会把下一行吃掉**（`$root` 变空，验证命令全在错路径上跑）。两条都写进
`DELIVERY.md` §五.7/§五.8。

**两次事故记一笔**（下次别再犯）：
1. 用 `pwsh` 的 `.Replace()` 往 Java 文件里塞**新中文**会把文件弄成乱码（编码边界）。
   教训：**带中文的文件改动一律用编辑工具，不用 shell**。那次靠 `git checkout` + 重做救回来。
2. `git commit -m` 里带 `"` 会把 shell 引号搞坏，提交静默失败而 tag 已经打上。
   教训：提交信息里只用 `「」`。
