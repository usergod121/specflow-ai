4.1 账本：append 与原子写

两段代码。第一段是 id 怎么来的，第二段是“不会写出半份文件”靠什么。

① 追加一行 = 先数行号

public synchronized Event append(Event event) {
    Event stamped = event.withId(rows().size() + 1L);   // id ≡ 行号
    Atomic.appendLine(file, Json.line(stamped));        // 一行一条，追加
    extend(Json.line(stamped));                         // 缓存接上，下次读 O(1)
    return stamped;
}

三行读法：数一下现有几行 → 盖号 → 写一行。所以别人问“第几条”，答案就是文件第几行。 synchronized 是唯一的写者保证，也是唯一一处并发控制。

② 整份替换 = 同目录临时文件 + 改个名

Path temp = file.resolveSibling(file.getFileName() + ".tmp");
Files.writeString(temp, content, UTF_8, CREATE, TRUNCATE_EXISTING, WRITE);
Files.move(temp, file, REPLACE_EXISTING, ATOMIC_MOVE);   // 原子

两个细节都是踩出来的：临时文件必须和目标在同一目录（跨盘改名会退化成复制 + 删，又变回写一半）； 读的时候要剥掉 BOM（记事本写出来的文件，第一个字符是 U+FEFF，会让路径解析莫名其妙地失败）。

边界：没有 fsync。断电可能丢最后几行，但不会出现半份文件。这一档取舍写在 README.md 的已知限制里，不装成有数据库级持久性。

完整实现：core/EventLog.java、core/Atomic.java。往下：4.2 流程源码。
