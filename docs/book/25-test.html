⑤ 测试：在副本里逐条验，结论与证据写回清单

这一格跑在项目副本 + 真容器里，改不坏你的项目。它交的东西是：每条用例的结论、证据，和一份总结。

点「跑测试」

Api.testRun → startTestRun(list, focus=null) ├ requireReachable(TEST,"跑测试") ├ CaseList.load(...) 读 cases.json ├ Runs.start(TEST,"run") └ body: ├ TestSandbox.prepare(...) │ ├ copyTree(项目 → flow/<id>/sandbox/<runId>) 整份副本，含未提交的改动 │ ├ Compose.render + up 起测试容器 │ └ preflight：工具在不在、目录挂对没有 ├ TestAgent.run(...) 逐条验 └ 收场：容器 down -v + 删副本

每一轮里有什么

工具干什么
bash在容器里跑命令（带超时；高危命令走审批）
read_file / read_list读副本里的文件
case_update写回一条用例的结论 + 证据；判 PASS 时引擎会问自己“这条用例期间真调过工具吗”，零调用直接拒
phase切「准备 / 验收」阶段，验收期源码冻结（Frozen）
submit这一轮验完了，交差

换到新一条用例时回调一次 sandbox.reset()，跑 env.yaml 里那条 reset 命令，让每条用例从已知状态开始。 单条预算 12 轮（准备阶段多给 8 轮），整轮 max(60, 用例数×12+20)。

跑完之后的三个按钮

提交 Api.testSubmit 清单里还有 PENDING → 拒；否则写 summary.md，并把这段总结写进 ④ 的 feedback（回喂开发） 接受 Api.testAccept freeze(TEST) → 闭环；顺手处置 ⑤ 留下的写前快照 重试这一条 Api.testRetryCase {id} 把这一条改回 PENDING 再只验它；单条最多重试 3 次（计数落在 facts 的 retries:<id>）

闸：清单里没有 PENDING 且已提交。
断点：跑到一半被杀，checkpoint.json 记着“验到哪一条、下一步干什么”，可以接着跑； 它只是一份提示，真相永远是 cases.json 和 events.jsonl。
