源码 3：账本 —— append 与原子写

两段代码，都在 core/。第一段是 id 怎么来的，第二段是“不会写出半份文件”靠什么。

① 追加一行 = 先数行号

public synchronized Event append(Event event) {
    Event stamped = event.withId(rows().size() + 1L);   // id ≡ 行号
    Atomic.appendLine(file, Json.line(stamped));        // 一行一条，追加
    extend(Json.line(stamped));                         // 缓存接上，下次读 O(1)
    return stamped;
}

数一下现有几行 → 盖号 → 写一行。所以“第几条”就是文件第几行；界面断线重连、进程重启都接着这个数往下读。 synchronized 是唯一的写者保证，也是唯一的并发控制。

② 整份替换 = 同目录临时文件 + 改个名

Path temp = file.resolveSibling(file.getFileName() + ".tmp");
Files.writeString(temp, content, UTF_8, CREATE, TRUNCATE_EXISTING, WRITE);
Files.move(temp, file, REPLACE_EXISTING, ATOMIC_MOVE);   // 原子

两个细节都是踩出来的：临时文件必须和目标同一目录（跨盘改名会退化成复制 + 删，又变回写一半）； 读的时候要剥掉 BOM（记事本写出的文件第一个字符是 U+FEFF，会让路径解析莫名其妙地失败）。

③ 读：按 (大小, 修改时间) 判断要不要重读

Snapshot cached = CACHE.get(file);
if (cached != null && cached.size() == size && cached.mtime() == mtime) return cached.rows();
fresh = Files.readAllLines(file);     // 变了才整份重读

界面改成 SSE 之后每 250 毫秒读一次尾巴，没有这层缓存等于每秒把整个文件读四遍。这也守住一条规矩： 盘是唯一真相，内存只是副本。

④ 回退时截断：先留副本

EventLog.truncateTo 在截之前先 Atomic.copy 一份 events-invalidated-<时间>.jsonl。 回退作废的是“状态”，不是“记录”——用户点回退往往正因为刚才那步失败了，把失败原文一起删掉，他就再也说不出报的什么。

边界：没有 fsync。断电可能丢最后几行，但不会出现半份文件。这一档取舍写在 README 的已知限制里，不装成有数据库级持久性。
