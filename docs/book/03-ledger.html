2.1 账本怎么记账

账本只干三件事：追加一行、整份换掉一个文件、回答某样东西在哪。 这一页只提三个名字：EventLog、Atomic、Layout。

追加一行

写的人（只有一个） │ append(事件) ▼ EventLog ├ 先数现在有几行 ──▶ 新 id = 行数 + 1 ← id 就是行号 ├ 追加到 events.jsonl（一行一条） └ 顺手把内存里的缓存接上，下次读不用重扫 读的人（可以有多个） │ read(from) ▼ └ 文件大小或修改时间变了就整份重读，没变就用缓存

所以「从头读到第几条」和「文件的第几行」是同一个数。界面断线重连、进程重启，都接着那个数往下读，不重不漏。

整份换掉

所有 JSON 不走追加，走替换：写到同目录下的临时文件，再改名盖过去。改名是原子的， 所以目标文件永远要么是旧的完整版、要么是新的完整版，不存在写了一半的中间态。

路径只问一处

Layout 回答“某样东西落在哪”。别处不许自己拼字符串——拼错一层目录的错， 只在真跑起来时才现形。

代价：id 靠“当前行数 + 1”算出来，所以只能有一个写者。两个进程写同一个项目会算出重复 id。 单实例是这套设计的前提，不是保证。
