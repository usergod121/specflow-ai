全局 2：五个节点共用的东西

下面八件东西不属于某一个节点，五个节点都在用。认这八件，比认五十个类有用。

件干什么在哪
事件流发生过的每件事一行，一个写者，id ≡ 行号；四种 type：log / tool / result / gatecore/EventLog core/Event
闸能不能动只由一处判；返回空串＝能过，否则就是给用户看的那句话；被拦时写一条 gate 事件并 409flow/Gates Gate Facts · FlowService.requireReachable / freeze
动作表每格有哪些按钮、叫什么、进页头还是进「⋯」，只在这里声明一次，随 /api/flow 下发flow/Actions
运行登记一段活：立刻返回 202 + 游标、同一时刻只许一段、收场只写一条结论flow/Runs · 同步活走 core/Jobs
叫停立取消标记 + 杀它起的整棵进程树；后台活按 CANCELLED 收场，同步活回「已按你的意思停下」core/Jobs.cancelAll · Runs.cancel
预算三把尺：等多久（时间）、问几次（轮次）、调几次（工具数）。到点各有自己的收场档env/Budgets · agent/LoopLimits · test/CaseBudget
快照与留档改项目之前拍原文（只拍白名单里的文件）；每段活开工/收场各记一行，用来判断有没有被杀过flow/Snapshot · flow/Journal
错误口径错误正文恒为 {"error":"一句话"}；400 参数、409 现在不能这么做、500 引擎自己炸了web/Errors · ApiException · FlowRejected

界面只做三件事

GET /api/flow ──▶ 五格状态、那句话、动作表、running ──▶ 画 点按钮 ──▶ POST ──▶ 不管成功还是 409，都再问一次 /api/flow ──▶ 重画 换项目 ──▶ 清掉上一套（流程/事件/失败条/游标）──▶ 重新问、重新连流

没有本地判断：按钮禁不禁用、显示哪句话，全看后端。唯一特殊的是「叫停」——平时在「⋯」里，跑起来时被提到页头最前。

为什么强调“一处”：判据写两处就会出现“界面说能点、后端回 409”； 按钮文案写两处就会出现“加了一个动作，只有一半页面有”；路径拼两处就会出现“少一层目录”。 这八件里有一半的存在理由就是“只许有一处”。
