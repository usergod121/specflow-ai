3.2 环：类与一次回合的调用链

包 agent/ 18 个类、agent/tools/ 8 个。用到一半的就这几个。

类管什么
Loop回合、四道闸、工具派发、锚点记忆、压缩时机
Protocol只认两种代码块；认不出来时的补问话术
Compact上下文压缩：系统规矩 + 任务书 + 锚点 + 尾巴
StuckCheck打转：第 4 次提醒、第 6 次判死
Tool / ToolRegistry / ToolResult工具接口、按名字派发、成功失败两态
Dev / Probe / CasesAgent / EnvAgent四个节点的任务书与工具装箱

一个回合

Loop.run ├ progress.cancelled() 被叫停就收场，不再问模型 ├ Compact.maybe 太长就压 ├ turn(messages) │ ├ ask() 真正花钱的那一步 │ ├ Protocol.parse 两种块：动作 / 交差 │ └ 认不出来 → 补问，最多两次，算同一轮 ├ 交差 → 收场 └ runTool ├ 推一条“开始跑某个工具”事件 ├ 工具执行（外面套着预算 / 打转 / 白名单三层） ├ 推一条“跑完了 + 结果”事件（同一条 id 成对） └ 结果入历史；顺手记下“动过哪个路径 / 这次为什么失败”

装箱顺序

new Whitelist( ← 只许动白名单里的文件（最外层，最后拦） new StuckCheck( ← 重复到一定次数就判死 new CaseBudget( ← 每条用例的轮次预算 new ApplyPatchTool(root) )))

顺序不能换：预算得先扣（不然一直不花钱判不出打转），打转要看全动作（不然看不清重复）， 权限放最外面（不管什么原因，越界一律不执行）。

工具坏了不抛异常、不崩循环：注册表统一翻成“失败 + 原因”喂回模型。它自己会换条路再试。
