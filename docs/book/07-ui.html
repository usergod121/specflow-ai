2.5 界面怎么不长脑子

界面只做三件事：把后端说的画出来、把人的动作发出去、把结果重新问一遍。 判断一概不做。三个名字：/api/flow、store.refresh()、PageHead。

只认一份数据

GET /api/flow ├ 五格：id、状态、那句话（为什么不能点）、事实 ├ 每格的按钮：id、文字、悬停说明、主按钮/危险、进页头还是进「⋯」 └ 现在有没有活在跑 界面拿这一份画左侧进度、状态胶囊、按钮条、那句话。 按钮怎么摆、能不能点，全看后端；前端只负责“按 id 找到处理函数”。

只走一个刷新的口

人点按钮 → 发出动作 → 不管成功还是被拒（409），都再问一次 /api/flow → 用新状态重画 换项目：清空上一套（流程、事件、错误条、游标）→ 重新问 → 重新连流 有活在跑：每 1.5 秒补一次问，防止推送断了之后按钮永远灰着

这样做每次动作多一个很小的请求，换来的是一件事：界面不会显示后端已经不这么认为的旧状态。

唯一的例外：叫停

平时“叫停”在「⋯」里，跑起来的时候被提到页头最前面，因为它是唯一能解开死锁的按钮。 这个提升规则写在页头组件里，按钮本身仍然是后端声明的那一枚。

踩过的坑：按钮的声明漏了“叫停”，或者界面把它藏进折叠里——提示写着“点叫停”，用户却找不到。 现在三处都有断言：声明里有、响应里有、没活在跑时页面上不许画出来。
