三条铁律

铁律意思
一个写者日志、工具、闸、收场全从同一处追加
id 恒等于行号游标与“第几条”是同一个数，重启接着数
盘是唯一真相内存只是副本，按文件大小与修改时间校验，对不上整份重读

十二条不变式

原文在 docs/ARCHITECTURE.md §4，这里只留一句一条。

#不变式#不变式
1一个写者；id ≡ 行号7崩溃可恢复：开工写一笔、收场写一笔，启动时扫一遍
2一个事实只有一个名字8模型与命令各只有一个出口；模型写的命令只在容器里跑
3产物只写一处落点9界面说明 ≤ 6 个汉字，状态名固定四档
4长任务只有一个过程口10日志只有四种类型，渲染最新在上
5闸只有一处判据，前端零判据11改完必须读得回来：人改的东西下一处要现读
6写项目前先拍快照，写文件一律原子12“做完了”= 输入有人给、输出有人用

边界

边界现状
单实例没有跨进程锁。两个引擎开同一项目会丢事实更新、可能重复 id；单实例是前提
持久性原子替换保证“不出半份文件”，但没做 fsync，断电可能丢最后几行
跨文件一致性没有事务。恢复粒度是“重跑这一步”，不是回放日志到一致点
同步任务互斥只有后台运行串行；起环境/编译/生成用例之间没有锁，靠界面按钮变灰挡
叫停杀得掉进程，打不断正在飞的模型调用
崩溃恢复的测试有实现、有调用点，没有单测，靠手工杀进程验证
平台Windows + Docker Desktop 实测；只监听回环地址；无鉴权

踩过的坑（一行一条）

细节与取舍在 docs/v3/DECISIONS.md 和 docs/DELIVERY.md。

现象根因现在的做法
五个页面只有状态、没有按钮动作表没随响应下发响应里必带，测试断言
按钮一直灰着禁用条件只在挂载时算一次每次渲染重算
提示让点叫停，页面上没有声明漏了、或藏进折叠里跑起来插队到页头；三处断言
换了项目还显示上一条流程只换了外壳，没重拉换项目全量重置
探针只列“要改”，不列“要新增”校验把不存在的路径判死要改 + 要新增都进白名单
④ 只会改、不会建工具只有改文件补了一个写新文件的工具，也过白名单
④ 一跑就到上限轮次写死，与白名单规模无关按白名单文件数算
改了上下文，下一处没反应读的是启动那一刻的快照配置与产物一律现读
PASS 的证据是“资源不存在”只认模型口供引擎数自己的工具调用，零调用就拒
起环境刷新一下提示就没了那句话只在局部变量里落盘，正在跑的步骤单独显示
环境“已就绪”但声明文件不存在只看历史标记，不看盘以“文件真在盘上”为前提判
编译命令填了，闸说还是空的配置只读一次每次问盘
容器里构建退出码 1与宿主共享产物目录，写权限不足副本里编
