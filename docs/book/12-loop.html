全局 3：环 —— 模型是怎么动手的

① 到 ⑤ 的 Agent 都跑在同一个循环上（agent/Loop）。这一页讲清一轮里发生什么、工具怎么被包起来。

一个回合

Loop.run 每轮： ├ progress.cancelled() 叫停了就收场，不再问模型 ├ Compact.maybe(...) 上下文太长就压（本地算，不花钱） ├ turn(messages) 问模型 → Protocol.parse 认这一轮想干什么 │ ├ TOOL → runTool │ ├ ANSWER → 收场（DONE） │ └ UNPARSABLE → 当场补问，最多两次，算同一轮 └ 四道闸各自收场：轮次用完 / 工具调太多 / 输出太长 / 超时

一次工具调用，发生了什么

runTool(parsed) ├ 推"开始跑 xxx"事件（动手之前推，bash 能跑十分钟） ├ 查注册表，调 tool.run(args) │ └ 外面套着装饰器：预算 / 打转 / 权限（见下） ├ 推"跑完了 + 结果"事件（与上一条同 callId，界面合成一枚 chip） ├ 结果作为一条普通消息塞回对话（失败就是 {"ok":false,"reason":"…"}） └ 顺手记锚点：动过哪个路径、这次为什么失败

工具怎么包起来

工具都是同一个接口，所以能一层层套。外层先跑前段、再交给里层、最后跑后段：

// ④ 开发：改文件 StuckCheck( Whitelist( ApplyPatchTool ) ) // ⑤ 测试：验用例 CaseBudget( StuckCheck( Frozen( WriteFileTool ) ) )
层它看什么越界/打转时
CaseBudget这条用例还剩几轮用完就拒，并提示标 SKIPPED
StuckCheck同一个调用（工具名 + 参数原文）连着第几次第 4 次提醒、第 6 次让它标 ERROR 收场
Whitelist / Frozen这个路径在白名单里吗 / 现在是验收阶段吗直接拒，不执行

顺序有意义：预算先扣（被拒的调用也算用了一轮）；打转要看模型提交的调用，与被权限拒掉无关； 权限紧挨真工具，是最后一道。
