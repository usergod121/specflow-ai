1.2 数据流：点一下「跑测试」之后

只跟数据走一遍，不看任何类。八步。

人点按钮 │ 1 界面发出请求，把按钮变灰 ▼ 流程 │ 2 判：这一步现在许不许跑（不许就回一句话，什么也不做） │ 3 登记：起一段活，立刻回「已开始」，不让人等 ▼ 环 │ 4 准备战场：复制项目、起容器、预检 │ 5 一轮一轮来：压缩上下文 → 问模型 → 认它的动作 → 跑工具 → 结果喂回去 ▼ 产物 │ 6 工具把结论写进用例清单；每次写都是整份替换，不会半份 ▼ 收场 │ 7 事件流补一条「结论」（页面上的结论只有这一个来源） │ 8 界面重新问一遍流程，把新状态画出来

盘上留下了什么

<项目>/.specflow/ project.yaml 编译命令、模型配置 人改，每次现读 local.env 密钥 不回显、不进日志 env.yaml 环境声明 ① 的产物，可手写 flow/current 当前流程 id flow/<id>/flow.json 五格状态与事实 ← 判据读它 flow/<id>/events.jsonl 发生过的事 ← 界面读它 flow/<id>/cases.json 验收清单与结论 flow/<id>/snapshot/ 改之前的原文 ← 回滚读它 flow/<id>/runs/ 每次运行的开工/收场 ← 崩溃恢复读它

写全走一条路（先写临时文件再换名），所以读的人看到的永远是完整的旧版或完整的新版。 读的时候看一眼文件大小和修改时间，没变就用上次读到的，变了整份重读。

没有数据库是刻意的：这些文件人要能直接打开、直接改。代价是"跨文件一致性"没有事务兜底——所以恢复的粒度是「重跑这一步」，不是回滚。
