源码 1：闸、冻结、收场

三段代码，回答三个问题：凭什么判、判完之后动什么、一段活怎么收。都在 flow/。

① 闸：先看顺序，再看这一格交的东西够不够

public static String blocked(Node node, Facts facts, Map<Node, State> states) {
    Node previous = node.previous();
    if (previous != null && states != null && states.getOrDefault(previous, LOCKED) != DONE) {
        return "上一步「" + previous.title() + "」" + word(was)
             + "：先把「" + previous.title() + "」做完并冻结，再动「" + node.title() + "」。";
    }
    return blocked(node, facts);        // 每格自己的门槛，表在 Gates.TABLE
}

返回空串＝能过；返回一句话＝不行，那句话原样给用户看（也是 409 的正文）。所以“为什么点不动”不用前端自己猜。

② 冻结：判过之后才动状态，顺手记一个游标

public synchronized void freeze(Node node) {
    FlowState state = synced();
    String blocked = Gates.blocked(node, facts(state), state.states());
    if (!blocked.isEmpty()) {
        events().append(Event.gate(0, node.key(), blocked));   // 留档：为什么不让往下走
        throw FlowRejected.conflict(blocked);                  // 409
    }
    state.setState(node, State.DONE);
    state.note(node, Map.of(Facts.FROZEN, "true"));
    ...
    state.note(node, Map.of(Facts.CURSOR, String.valueOf(events().lines())));
    store.save(state);
}

那个游标是给“回退”用的：回到某一格要截事件流，“截到哪”只有冻结这一刻说得清。截之前先留副本——回退作废的是状态，不是记录。

③ 收场：结论只有一条，来源只有一个

if (mine.cancelled())        status = CANCELLED;   // 叫停优先，不写成失败
else if (thrown != null)     status = FAILED;
else if (errorId > doneId)   status = FAILED;      // 有报错就没算完
else                          status = DONE;
log.append(Event.result(..., payload));

轮次、模型调用次数、编译错误这些只有干活的知道，它“说一句话”写进事件；Runs 只把这一段事件收口成一份载荷。界面画那一页就只读这一条。
