2.2 流程怎么管进度

流程管两件事：这道台阶能不能往下走，和一段活怎么起、怎么停、怎么收场。 三个名字：Gates、FlowService、Runs。

五级台阶

① 环境 ──▶ ② 探针 ──▶ ③ 用例 ──▶ ④ 开发 ──▶ ⑤ 测试 │ │ │ │ │ 一格一个闸：判的不是“我做完了没”，而是“我交出来的东西够不够下一步用” │ │ │ │ │ ▼ ▼ ▼ ▼ ▼ 冻结 冻结 冻结 冻结 提交 → 接受 每格三态：未开始 ──▶ 待完成 ──▶ 已完成 └── 前驱没完成就叫“未开始”，点它会回一句话，不报错也不动手

闸是纯函数：给同样的状态和事实，永远给同样的结论或同一句话。 界面上那句“不能跑测试，前置开发还没做完”就是它返回的原文。

一段活的一生

点按钮 │ 判（不过 → 回一句话，什么也不写） │ 登记：立刻回“已开始”，给一个读事件流的起点 ▼ 后台一个线程跑：过程一边跑一边往事件流写 │ ├ 跑完 → 收场写一条“已完成 + 结论” ├ 出错 → 收场写一条“失败 + 原因”，异常原文不吞 └ 被叫停 → 收场写一条“已停下”，并杀它起的整棵进程树

同一时刻只允许一段活。第二段直接拒绝，理由是两段活会同时改同一个项目，而留档里看不出是谁改的。

踩过的坑：闸的判据曾经写在两处（路由一处、界面一处），于是界面说能点、后端回 409。 现在判据只有一处，前端一行都不许有，只显示那句话。

想看判据和收场的代码 → 4.2 流程源码；想看有哪些类和调用链 → 3.1 流程的类。
