源码 2：回合与压缩

两段代码，都在 agent/。第一段是整个循环，二十行，没有玄机。

① 回合

while (round < limits.maxRounds()) {
    round++;
    if (progress.cancelled()) return outcome(CANCELLED, round, "用户叫停", ...);
    lastCompact = Compact.maybe(messages, anchorTable(),          // 太长就压
            limits.compactChars(), limits.compactKeepTail());

    Turn turn = turn(messages);                    // 问模型 + 认它（认不出同轮补问）
    if (turn.status() != null) return outcome(turn.status(), ...);
    if (turn.parsed().kind() == ANSWER) return outcome(DONE, ...);
    if (++toolCalls > limits.maxInstalls()) return outcome(TOOL_LIMIT, ...);

    Signal signal = runTool(round, turn.parsed(), messages, calls);
    if (signal != null) return outcome(DONE, "模型交差", ...);
}
return outcome(ROUND_LIMIT, round, "轮次上限用尽，模型还没收工", ...);

四道闸各有自己的收场档，所以“它为什么停了”永远答得出来：轮次用完、工具调太多、格式一直不对、超时、被叫停。

② 压缩：锚点由循环自己攒

private void remember(Map<String, Object> args, ToolResult result) {
    Object path = args.get("path");
    if (path instanceof String one && !one.isBlank() && touched.size() < ANCHOR_PATHS) {
        touched.add(one.strip());                  // 动过哪些路径
    }
    if (result != null && !result.ok() && failures.size() < ANCHOR_FAILURES) {
        failures.add(第一行, ≤90 字);                // 最近几次为什么不行
    }
}

压缩保四样：系统规矩、原始任务书、最后几条对话、这份锚点。锚点不是业务知识，是循环每轮都看在眼里的东西，所以由循环自己记—— 原来交给调用方拼，五格里只有一个拼了，其余一压缩就丢，模型开始重复读同一个文件。

③ 认不出来时的那句补问

if (parsed.kind() == UNPARSABLE && retries < 2) {
    messages.add(Llm.Msg.user(Protocol.retryNotice(parsed.problem())));   // “你给的是 java 块…”
    continue;   // 同一轮内重问，不扣轮次
}

补问两次还认不出来才以 UNPARSABLE 收场，话术带上它写的原文。理解成“没听懂”，不是“失败”。
