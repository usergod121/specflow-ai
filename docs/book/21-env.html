① 环境：把项目装进一个能构建的容器

这一格要交两样东西：一份环境声明（env.yaml）和一条能跑通的编译命令。 四个按钮，四条链。

点「探测环境」

Api.envAgent ├ FlowService.requireReachable(ENV,"探测环境") 判：前驱…① 是第一格，直接过 ├ Runs.start(ENV,"env-agent") 登记：202 + 游标 └ body: EnvAgent.run() ├ Loop 跑 read_list / read_file（只读，不动项目） ├ 交回 env.yaml 全文 + 一条编译命令 + 几句说明 ├ ok → Atomic.write(layout.envYaml(), 草稿) ← 探测完就落盘 │ writeCompile(project, 命令) ← 写进 project.yaml 的 build.compile │ FlowService.note(ENV,{envDeclared,compileCommand}) └ !ok → progress.fail(原因)，旧文件一个都不动

点「起环境」

Api.envUp（同步，不走 Runs；用 Jobs.register 登记） ├ Environment.up(progress) │ ├ Compose.render(env.yaml) 声明 → compose.yaml（写在 flow/<id>/env/<时间>/） │ ├ docker compose up -d app 容器：非 root、cap_drop、只挂项目树 │ ├ init 逐条跑（可在依赖容器里跑，stdin 可喂项目里的文件） │ └ 任何一步失败 → down -v 收干净，不留半成品 ├ Capabilities.verify(...) │ ├ command -v 认构建工具（便宜） │ └ 在容器里的副本（/tmp/specflow-build）真构建一次（贵） │ 失败且命令带 \ → linuxSafe 改成正斜杠再试，过了就写回 project.yaml └ FlowService.note(ENV,{envReady,containerBuild,containerDetail})

点「编译」 / 「跳过」

编译走 Api.envCompile → Compiler.compile，在宿主机上跑（快速反馈），命令过 CommandGuard。 跳过走 Api.envSkip，把 envNotNeeded 记成事实——闸的另一条出路。

这一格交出去什么 · 闸问什么

产物落在哪
环境声明.specflow/env.yaml
编译命令.specflow/project.yaml 的 build.compile
事实flow/<id>/flow.json：envDeclared envReady containerBuild compilePassed

闸：编译命令非空 且（环境起过 或 声明不需要环境）。

最常见的三个失败：镜像里没有构建工具（改 image 或 init）；编译命令是 Windows 写法（自动改一次并写回）； Docker 没启动（话术直接说去开 Docker Desktop）。
