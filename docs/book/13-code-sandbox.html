4.4 验收：沙箱、预算、审批

三段。第一段是战场怎么铺，后两段是“凭什么停”和“危险命令问谁”。

① 沙箱：副本也放在流程目录里

Path copy = layout.flow(currentFlowId).resolve("sandbox").resolve(runId);
copyTree(project.root(), copy);                              // 整份复制，含未提交的改动
Atomic.write(copy.resolve("compose.yaml"), Compose.render(config, copy, projectName));
up(copy, ...);                                               // 起容器，工作目录指着副本
preflight(...);                                              // 预检：工具在不在、目录挂对没有
// 收场：down -v + 删副本，下一轮从干净的一份开始

副本不是放系统临时目录，而是放在这一次运行的目录里——出问题时能直接进去看，跑完连卷一起收掉。

② 预算：12 轮 + 准备宽限 8 轮

public static final int DEFAULT_PER_CASE = 12;     // 一条用例能问几次模型
public static final int PREP_GRACE      = 8;       // 准备阶段（还没到第一条）多给几轮

换到新的一条用例时回调一次 onCaseStart         → ⑤ 用它跑 env.yaml 的 reset
预算用尽 → 标 SKIPPED（不是结论），可以单条重试，最多 3 次

“每条用例 reset”这一栏原本只有命令行用过，测试跑的时候一次都没调——所以第二条用例开始就带着上一条的脏数据， 结论会失真。现在换用例那一刻回调一次，失败只提醒不中断。

③ 审批：三态，不是一个布尔

允许   → 执行
拒绝   → 不执行，告诉模型“用户拒绝了这条”
没人理 → 等满 2 分钟按拒绝处理，但话术不同：说清“没人回你，不是否决”

为什么分开：说“你被拒绝了”，模型会换条路继续试；说“没人回你”，它才知道该收场。 两者混成一个布尔，模型的行为就永远对不上现场的真相。

踩过的坑：sudo 原来在“问一句”的名单里，用户等了 187 秒回“允许”， 结果容器里根本没有 sudo。现在这类命令直接拒，并指名去改 env.yaml。

完整实现：test/TestSandbox.java、test/CaseBudget.java、test/Approvals.java、 env/Capabilities.java。查表：铁律与不变式。
