1 · 五个模块

整个系统只有五块，按依赖方向从下往上：账本托着流程，流程驱动环和环境，界面在最外面只做转发和显示。 五块之外没有第六块，剩下的都是这五块里的细节。

┌────────────────────────────────────┐ 浏览器 / curl ─▶│ ⑤ 界面 web + frontend │ 只转发、只显示 └────────────────┬───────────────────┘ │ HTTP + SSE ┌────────────────▼───────────────────┐ │ ② 流程 flow │ 谁能动、一段活怎么跑 │ 五格 · 闸 · 动作表 · 运行 · 断点 │ └───┬────────────────────────┬───────┘ ┌────────────▼──────┐ ┌────────▼──────────┐ │ ③ 环 agent │ │ ④ 环境与验收 │ │ 问模型 → 跑工具 │ │ env + test │ └─────────┬─────────┘ └─────────┬─────────┘ └─────────────┬──────────────┘ ┌──────────────▼─────────────────────┐ │ ① 账本 core │ 事件流 · 原子写 │ EventLog · Atomic · Layout · Jobs │ 路径 · 进程 └────────────────────────────────────┘
模块一句话它管它不管
① 账本
core/ 14 个类		发生过的每一件事只追加一行，写在哪个文件由一处决定 事件流、原子写、路径、子进程、模型调用、日志流程判据、Agent 行为
② 流程
flow/ 16 个类		五级台阶，一步一个闸；一段活怎么起、怎么停、怎么收场 五格状态、闸、动作表、运行登记、快照、断点怎么改代码、怎么起容器
③ 环
agent/ 18 个类 + tools/ 8		问模型 → 认它的动作 → 跑工具 → 结果喂回去 ReAct 循环、协议解析、上下文压缩、打转检测、工具集能不能开始（那是闸的事）
④ 环境与验收
env/ 9 · test/ 13		把项目变成能跑的环境，再在副本 + 容器里逐条验 compose 渲染、起停、守卫、编译、能力校验、沙箱、用例、审批Agent 怎么想
⑤ 界面
web/ 7 + 前端 19 个文件		把后端说的话翻译成页面，不自己判断任何事 40 条路由、会话、SSE、动作表渲染、失败条判据一行都不许有
这张图的用法：看代码时先定位它在第几块。发现某个类同时干了两块的事 （比如路由里出现了判闸逻辑），那就是一处设计漏了。

2 · 数据流

2.1 一次「点跑测试」

人点按钮 │ ├─① 界面 api.js POST /api/node/test/run；store.busy 记一笔 │ ├─② 流程 Api.testRun → FlowService.requireReachable(TEST) ← 闸；不过就 409 + 一句话 │ → Runs.start(TEST, "run", body) ← 登记 + 立刻 202 + cursor │ ├ Journal.begin(runId) 写 runs/.jsonl 的 BEGIN │ └ 单线程池跑 body │ ├─③ 环 TestAgent.run：TestSandbox.prepare() → 副本 + 容器 + 预检 │ 每轮：Compact.maybe → 问模型 → Protocol.parse → 跑工具 → 结果入历史 │ 工具套三层：CaseBudget → StuckCheck → Whitelist/become-frozen │ 每条用例开始前跑一次 env.yaml 的 reset │ ├─④ 产物 工具写 cases.json（整份校验通过才原子替换）；结论与证据都在里面 │ └─⑤ 收场 事件流追加一条 type=result（那一页的结论只有这一个来源） Journal.end + facts.failed 落盘 + 计数器

2.2 盘上的落点

<项目>/.specflow/ project.yaml 编译命令 + 模型配置 人改，每次现读 local.env 密钥 人改，不回显不进日志 env.yaml 环境声明 ① 的产物，可手写 flow/current 当前流程 id flow/<id>/flow.json 五格状态 + facts ← 闸读它 flow/<id>/events.jsonl 统一归档日志 ← 界面读它 flow/<id>/probe.json cases.json summary.md flow/<id>/snapshot/ 写之前的原文 ← 回滚读它 flow/<id>/runs/<runId>.jsonl 每次运行的 BEGIN/END ← 恢复读它 flow/<id>/checkpoint.json 断点，可删 flow/<id>/env/<时间戳>/compose.yaml 渲染出来的 compose

2.3 三条不能破的约定

约定意思破了会怎样
一个写者events.jsonl 只有 EventLog.append 一处写，行号就是事件 id 两个写者各数一套 id，界面按 ?from= 拉取时重复或跳过
原子替换所有 JSON 写入走 Atomic.write：同目录临时文件 + rename 写到一半崩掉，留下半份文件，而且没人告诉用户这是崩溃留下的
闸只有一处Gates.blocked(...) 判，界面只显示它给的那句话 界面说能点、后端回 409，或者反过来；用户看到“按钮在，点了没反应”

2.4 三种「在跑」和一种「停下」

在跑的东西登记在哪怎么停
后台运行：② 跑探针 / ④ 跑开发 / ⑤ 跑测试flow/Runs（同一时刻只许一段） 立取消标记 → Loop 下一轮按 CANCELLED 收场
同步长任务：① 起环境 / 编译、③ 生成用例core/Jobs（进程登记表） 杀整棵进程树 → Api.stopIfCancelled 回「已按你的意思停下」
模型调用本身不在上面两处打不断，得等这一轮回来；这是已知边界

判据只有一处：Runs.cancel()（running || Jobs.running() > 0）。 路由不再自己判一次——判两次就会出现“按钮在、点了回 409”。

3 · 往下钻

每一块只讲三件事：里面有几件东西、一段真代码、一个踩过的坑。想看全部方法就打开对应的类。

3.1 ① 账本 core/

类职责
EventLog / Event单写者追加日志；读侧按 (size, mtime) 校验缓存
Atomic写盘唯一入口：临时文件 + ATOMIC_MOVE；读时顺手剥 BOM
Layout某样东西落在哪，只有这一处回答
Progress / EventProgress长任务说给自己的话，全部变成事件（不另开日志文件）
Jobs什么在跑、叫停杀谁：按“起它的那个线程”登记进程
public synchronized Event append(Event event) {
    Event stamped = event.withId(rows().size() + 1L);   // id ≡ 行号，重启接着数
    Atomic.appendLine(file, Json.line(stamped));
    extend(Json.line(stamped));                          // 追加后把缓存接上，O(1)
    return stamped;
}
坑：id 靠“当前行数 + 1”算，所以只能有一个写者。两个进程写同一个项目会算出重复 id—— 不会写坏文件（原子替换兜着），但会错位。单实例是前提，不是保证。

3.2 ② 流程 flow/

类职责
Node / State / NodeView五格与三态（LOCKED → READY → DONE）；界面看到的那一份
Gates / Gate / Facts一格一个判据、一张表、事实的名字常量
FlowService读状态、写 facts、冻结、回退（回退即作废下游）；所有变更 synchronized
Runs一段后台运行：立刻返回 202、同一时刻只许一段、收场只写一条 result
Journal崩溃恢复那本账：有 BEGIN 没 END 就是被杀过
Snapshot写项目代码前拍一份原文；accept / rollback 由人点
Actions每一格有哪些按钮，只在这里声明，随 /api/flow 下发
public synchronized void freeze(Node node) {
    requireReachable(node, "冻结");                 // 前驱没完成就 409
    String blocked = Gates.blocked(node, state.facts(), states());  // 唯一判据
    if (blocked != null) throw FlowRejected.conflict("不能冻结。" + blocked);
    save(state.withFlag(node, "done", "true"));     // Atomic.write 整份替换
}
坑：判据分散过一次——路由判一遍、界面判一遍，结果是界面说能点、后端回 409。 现在 Gate 是纯函数，前端一行判据都没有，只显示 blockedReason 那句话。

3.3 ③ 环 agent/

类职责
LoopReAct 本体：压缩 → 问模型 → 解析 → 跑工具 → 回喂；四道闸（轮次 / 工具数 / 输出长度 / 超时）
Protocol只认两种围栏：specflow-tool 是动作、json 是交差；认不出就同轮补问两次
Compact上下文压缩：确定性锚点 + 任务书 + 尾巴，不调模型
StuckCheck打转检测：第 4 次提醒、第 6 次判死
Tool / ToolRegistry工具接口与派发；异常一律翻成 ok=false 喂回模型，不崩循环
Dev / Probe / CasesAgent / EnvAgent四个节点的任务书与工具装箱
② 的四样产物语义校验（Probe.validate）谁在用
files④ 要读的文件必须真存在提示词「先读这几处」
changes写白名单：要改的 + 要新增的已存在的必须先列进 files；还不存在的放行Whitelist 包住 apply_patch 与 write_file，也决定轮次预算
context为什么这些地方相关只去空，不判真假提示词第二段
prompt这一轮做什么不许空，空了等于让它自己发明需求压缩时原样保住的那份任务书
while (round < limits.maxRounds()) {
    round++;
    if (progress.cancelled()) return outcome(CANCELLED, …);
    messages = Compact.maybe(messages, anchors.get(), limits.compactChars(), limits.compactKeepTail());
    Turn turn = turn(messages);                    // 认不出来就当场补问，最多两次
    if (turn.parsed().kind() == ANSWER) return outcome(DONE, …);
    if (++toolCalls > limits.maxInstalls()) return outcome(TOOL_LIMIT, …);
    if (runTool(round, turn.parsed(), messages, calls) != null) return outcome(DONE, "模型交差", …);
}
坑：锚点表原来交给调用方拼，五格里只有 ⑤ 拼了，②③④ 一压缩就只剩“system + 任务书 + 尾巴”， 上下文省下来了、最该留的那两句没了。现在由 Loop 自己攒“动过的路径 / 最近的失败”。

3.4 ④ 环境与验收 env/ + test/

类职责
EnvConfig / EnvConfigLoaderenv.yaml 的形状与校验（带行号、一次报全）
Compose / Environment渲染 compose、起停、inApp（唯一一条进容器的路）
Capabilities起完在容器里验能力：先 command -v，再在副本里真构建一次
Compiler / CommandGuard / Budgets宿主机编译、三档守卫、唯一超时换算处
TestSandbox⑤ 的副本 + 容器 + 预检；跑完连卷一起收
CaseList / CaseBudget / Approvals用例清单与状态机、逐用例预算（12 轮 + 准备宽限 8）、高危命令 y/n
// 容器侧的构建永远在副本里跑：/work 与宿主同一份，直接编会撞写权限
inCopy(compile):
  rm -rf /tmp/specflow-build && cp -a /work/. /tmp/specflow-build/
  && rm -rf /tmp/specflow-build/target && cd /tmp/specflow-build && ( compile )

PENDING → PASS / FAIL / ERROR / SKIPPED(预算用尽，可重试)
坑：容器里 mvn package 撞宿主文件的写权限，退出码 1 看起来像“镜像坏了”。 改成复制到 /tmp 再编，宿主的 target/ 一个字节不动，依赖还在外部缓存卷上，不用重下。

3.5 ⑤ 界面 web/ + 前端

类 / 文件职责
Api40 条路由：取参数 → 调下层 → 拼响应，判据一条都不在这层
Session「当前打开哪个项目」；打开时顺手 Journal.sweep() 收上一次的尾
Errors异常翻成 {"error":"一句人话"}；FlowRejected 带自己的状态码

4 · 三条铁律与十二条不变式

这一节是查表用的。违反任何一条，都算这一版失败。原始版本在 docs/ARCHITECTURE.md §4。

铁律（EventLog）意思
一个写者日志、工具、闸、收场全从 append() 出去
id 恒等于行号游标与“第几条”是同一个数，重启接着数
盘是唯一真相内存只是副本，按 (size, mtime) 校验，对不上整份重读
#不变式#不变式
1一个写者；id ≡ 行号7崩溃可恢复：BEGIN/END + 启动扫一遍
2一个事实只有一个名字（Facts 常量）8模型与命令各只有一个出口；模型写的命令只在容器里跑
3产物只写一处落点（问 Layout）9文案预算：界面说明 ≤ 6 汉字，状态名固定四档
4长任务只有一个过程口（Progress）10日志只有四种 type，渲染最新在上
5闸只有一处判据，前端零判据11改完必须读得回来：人改的东西下一处要现读
6写项目前先拍快照，写文件一律原子12“做完了”= 输入有人给、输出有人用
第 11、12 条是事后补的：前十条防的是“逻辑写错”，可真正捞出来的 bug 多半是接线错—— 东西都在、测试全绿、零报错，只是中间某一段没接上。判断一个功能做没做完，问三句： 输入谁给？输出谁用？调用点有几个？

附录 A 踩过的坑（一行一条）

细节与取舍在 docs/v3/DECISIONS.md 和 docs/DELIVERY.md；这里只留索引，忘了哪条来这儿找名字。

现象根因现在的做法
五个页面只有状态、没有按钮flowView() 没把 actions 拼进响应ApiTest 断言每格都带；冒烟测试拿声明和真实渲染对账
按钮一直灰着禁用条件写成字面量，挂载时求一次值就冻住每次渲染重算，读 store.busy
提示让你点叫停，页面上没有叫停藏在「⋯」里；running 只在事件流里更新onlyWhileRunning 提升到页头；/api/flow 就带 running
换了项目还显示上一条流程打开新项目只换了外壳，没重拉 flow、没停旧流openProject() 全量重置后再 refresh()
探针只列“要改”，不列“要新增”校验把不存在的路径判死changes = 要改 + 要新增；新路径只放 changes
④ 只会改、不会建工具只有 apply_patch装一个 write_file，同样过白名单
④ 一跑就到上限轮次写死 40，与白名单规模无关min(160, max(40, 12 + 白名单×8))
改了上下文，下一处没反应存在盘上，读的是启动那一刻的快照配置与产物一律现读，(size, mtime) 变就重读
PASS 的证据是“资源不存在”case_update 只认模型口供引擎数自己的工具调用：这条用例期间零调用就拒
起环境刷新一下提示就没了能力校验那句话只在局部变量里读自 facts（落盘），正在跑的步骤读 stage
“环境已就绪”但 env.yaml 不存在facts 只看历史标记，不看盘以“文件真在盘上”为前提算这两条
编译命令填了，闸说还是空的project.yaml 只在打开项目那一刻读一次Project.raw() 每次问盘
容器里构建退出码 1与宿主共享 target/，uid 1000 写不进去副本里编，见 3.4
逐条验越跑越慢用例的 reset 从没被调用过换用例那一刻回调一次

附录 B 边界与已知限制

边界现状
单实例没有跨进程锁。两个引擎开同一项目会丢 facts 更新、可能重复 id；单实例是前提
持久性原子替换保证“不出半份文件”，但没有 fsync，断电可能丢最后几行
跨文件事务没有。恢复粒度是“重跑这一步”，不是回放日志到一致点
同步长任务互斥只有后台运行串行；① 的起环境/编译、③ 生成用例之间没有互斥锁，靠界面 busy 挡
叫停杀得掉进程，打不断正在飞的模型调用
日志保留单次输出有 2000 行上限，但没有按天剪枝，长跑会变大
崩溃恢复的测试Journal.sweep() 有实现、有调用点，没有单测，靠手工 kill 验证
平台Windows 11 + Docker Desktop 上实测；接口只监听 127.0.0.1，无鉴权
