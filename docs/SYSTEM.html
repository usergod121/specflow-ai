第 0 部分

需求

0.1 要解决什么问题

给一个已有的项目和一个"要改什么"的需求，目前的做法是：人自己搭环境、自己读代码、 自己想验收标准、自己写代码、自己跑测试——每一步都在反复切换身份，而且"验过了"这三个字 没有任何证据支撑。

这个系统把这件事拆成五个有闸的站点，让每一步都有产物、有判据、有留档：

① 环境项目跑在什么容器里、怎么起、能不能构建
② 探针读项目，交出「改哪儿、怎么改」的上下文
③ 用例把一句模糊需求变成可逐条验收的清单
④ 开发在白名单内改真项目代码，每次交差编译一次
⑤ 测试在副本 + 真容器里逐条验，结论与证据写回清单

0.2 硬需求（这一版不许违反的）

#需求为什么它是硬的
R1五站语义与顺序不变它是"卡在哪一站"的唯一答案来源；一变，所有历史留档都失去意义
R2一个 bat 入口（起 / 停 / 销毁）用户明确要求"别让我自己敲命令"
R3前端尽量少改，只许加流式与必要按钮时间与风险都不允许重做界面
R4状态是人能打开看的文本排错时这一条比任何查询语言都值钱
R5不碰用户自己的旧实例（8770）那是他正在用的东西

0.3 非目标（刻意不做）

  • 不做全能 Agent：不让模型决定"下一步做哪一站"。顺序写死，模型只负责站内那一段活。
  • 不做多智能体群聊：五站已经是编排；自由对话会让"卡在哪"失去答案。
  • 不换数据库：事件流 id ≡ 行号 + 人能打开看，是这套东西最值钱的性质。
  • 不把引擎自己塞进容器：引擎要调 docker 造沙箱，给了 docker.sock 就等于给了宿主 root。

0.4 什么叫"跑通了"（验收口径）

  1. 端到端：真模型 + 真 Docker，五站从"起环境"走到"接受"，且 ④ 的成果由独立脚本核对（不采信 Agent 自述）。
  2. 单元与模块：闸、用例状态机、预算、守卫、事件流、断点、压缩、路由形状，每条都有测试。
  3. 界面：七个路由在真浏览器里零控制台错误、零失败面板；事件走 SSE。
  4. 收场：容器与卷能被一条命令收干净，且不动别人的东西。

第 1 部分

认识这个系统

1.1 一句话

给它一个项目 + 一句需求，它自己把五站跑完；每一站都有闸，上一站没冻结，下一站连点都点不动。

1.2 三层核心认知

第一层：它是流水线，不是全能 Agent

Agent 只是流水线上那几站的"手"。站序、每站产物、站与站之间的闸都不由模型决定。 这一条是整个系统可解释性的来源。

第二层：闸是纯函数

// flow/Gate.java —— 一格一个实现，签名只有这一行
String blocked(Facts facts);   // 空串 = 能做；否则就是直接给用户看的那句话
实现里不许读盘、不许看时间、不许写事件——同一份 Facts 永远给同一个答案。 于是闸能被单测钉死，而界面上的"为什么还不能点"与 409 的正文是同一句话。

第三层：状态是文件，事件是流水账

flow.json五格状态 + 每格产物（原子替换写）
events.jsonl唯一归档日志；行号 = 事件 id
cases.json / probe.json / summary.md人能直接改的产物

1.3 三条铁律 + 五条不变式

铁律（EventLog）意思
只有一个写者日志、工具调用、闸、收场，全从 append() 出去
id 恒等于行号追加前现读行数、盖号、写一行 → 游标与"第几条"是同一个数，重启接着数
盘上是唯一真相内存里那份只是副本，用 (大小, mtime) 校验，对不上就整份重读
不变式违反会怎样
事件只有一个写者两个写者各数一套 id → 界面拉取时重复或跳过（v2 之前就这样）
Event.id ≡ 行号重启后历史错位
一个事实只有一个名字（Facts 常量）写的人写 envConfirmed、读的人读 envReady → 闸永远看不见
Layout 是唯一路径权威四处各拼一遍字符串，必有一处少一层目录
长任务只从 Progress 一个口说话两条进度通道 → 界面读不到（用户原话"只听到风扇转"）

2.5 技术栈（以及为什么不选别的）

层选了什么为什么考虑过但没选
语言Java 17用户既有栈；records / 文本块让"数据类"写起来很薄Kotlin（团队不熟）
WebSpring Boot 3.5（只 starter-web + actuator）内嵌 Tomcat 一行起；不引 JPA/Security/Validation，暴露面越小越好Quarkus/Micronaut（生态更小）；Javalin（配置要自己写很多）

日志logback + MDC（req / run）一段运行能被 grep run=r-… 整段拉出来第三方追踪（单机没必要）

第 3 部分

契约与 API

3.1 五格状态机

LOCKED
→
READY
→ 冻结 →
DONE
LOCKED  前置没冻结：连点都点不动（409 + 一句话）
READY   这一格可以做活了，但还没冻结 —— 每次读都现推，不落盘
DONE    冻结了：下游随之解锁；回退会把下游一起作废
为什么 READY/LOCKED 不落盘：落盘就会"过时"。每次现推的代价是读一次 flow.json， 换来的是状态永远不骗人；只有 DONE 是记下来的（它代表"人确认过"）。

3.2 用例状态机（③ 的产物 → ⑤ 的结论）

生成时：  PENDING
验完：    PENDING → PASS（必须有证据原文）
        PENDING → FAIL（说清哪里不对）
        PENDING → ERROR（说清为什么没测成）
预算用尽：PENDING → SKIPPED（终态，但不是结论；可「重试这一条」）
重试：    SKIPPED / FAIL / ERROR → PENDING（只重验这一条）
提交时的五条机器判据：① 清单非空 ② 没有 PENDING ③ PASS 有证据 ④ 非 PASS 有原因 ⑤ 至少一条真结论——全是 ERROR 等于"没验"，把它当通过等于把"没验"说成"没问题"。

3.4 错误口径（四类，前端只认这四种）

状态码什么时候正文
400参数错（缺 id、节点名不认识、清单不合规）{"error":"一句人话"}
409闸拒绝 / 有活在跑还要换项目{"error":"不能跑测试。前置「开发」还没做完…"}
404静态资源找不到（浏览器要 favicon 那种）{"error":"没有这个资源"}，且不记 ERROR 日志
500只有真没料到的情况{"error":"接口炸了：…"}
闸拒绝是 409 而不是 500：它不是一个故障，是"这一步现在还不能做"。 正文就是界面上那句原话——用户看 409 的理由和看界面提示是同一句，不需要翻译。

代码：EventLog.append（这是全系统最要紧的 7 行）

public synchronized Event append(Event event) {
    Event stamped = event.withId(rows().size() + 1L);   // ① 行数 + 1 = id
    String row = Json.line(stamped);
    Atomic.appendLine(file, row);                       // ② 只追加，一次写一行
    extend(row);                                        // ③ 把内存快照接上（O(1)）
    return stamped;
}
为什么"盖号"要现读行数：进程重启后计数器会从 0 重来，而界面的游标停在"第 1200 条" —— 两边一错位，要么重复要么漏。现读行数之后，行号就是唯一的号源。

代码：EventLog.rows()（"不缓存"那条铁律怎么守住的）

Snapshot cached = CACHE.get(file);
long size = Files.size(file), mtime = Files.getLastModifiedTime(file).toMillis();
if (cached != null && cached.size() == size && cached.mtime() == mtime) return cached.rows();
List<String> fresh = List.copyOf(Files.readAllLines(file));   // 对不上就整份重读
CACHE.put(file, new Snapshot(size, mtime, fresh));
return fresh;
缓存的是"盘上内容的副本 + 校验和"，对不上就整份重读——盘上永远是唯一真相。 必须加它的原因：界面改 SSE 后每 250 毫秒读一次"从第 N 行到末尾"，不缓存等于每秒读几遍全文件。

4.2 flow：流程（8 个类）

类职责
Node五站枚举；ordinal() 就是顺序；previous() 给闸用
StateLOCKED / READY / DONE
Facts闸的输入（13 个字段），事实名字只在这里出现一次
Gate + Gates一格一个实现 + 一张表；Gates.blocked(n,f,states) 是完整闸（含顺序那条硬规则）

代码：Gates 的两个重载（这是最容易被改错的地方）

// 完整闸：先判顺序，再判这一格自己的门槛
public static String blocked(Node node, Facts facts, Map<Node, State> states) {
    Node previous = node.previous();
    if (previous != null && states != null && states.getOrDefault(previous, LOCKED) != DONE) {
        return "上一步「" + previous.title() + "」" + word(was) + "：先把…做完并冻结…";
    }
    return blocked(node, facts);       // 只判这一格的门槛（给"自己满足自己门槛"的场合）
}

关键机制（10 条）

5.1 两条编译：宿主机 vs 容器

宿主机 Compiler容器 Capabilities
问的问题这台机器能不能构建下游真要用的时候能不能用

事故：用户项目的 env.yaml 用 eclipse-temurin:17-jdk（只有 JDK，没有 Maven）。 ① 在宿主机编译（宿主装了 Maven）→ 绿灯；⑤ 进容器 mvn 找不到，自己下载安装， 烧掉 60 轮里的 28 轮、34 分钟，12 条用例 0 条结论。

5.2 三层预算

层上限超了怎么办
整轮max(60, 用例数×12+20) 轮失败收场，但如实报已写下几条结论
每条用例12 轮（+ 准备宽限 8）标 SKIPPED；可「重试这一条」
单条命令min(Budgets, 600s)终止，并说清"容器里那半截可能还在跑"
为什么单条命令要另设上限：Budgets 是给我们自己的长任务用的（拉镜像、构建）， 而 ⑤ 里跑的是模型写的命令 —— 实测它写了个死循环程序，在容器里 150% CPU 转了 15 分钟。

5.3 守卫三档

档判据处置
一律拒--privileged、docker.sock、-v /:/host、--net host、写块设备直接失败，不问
停下来问dd、curl … | sh、chmod 777、成片删y/n 面板，最多等 2 分钟；超时按拒但话术不同
v3 新增sudo（容器里不可能成功）／装工具链直接拒 + 指名去改 env.yaml
事故：原来 sudo 在"问一句"里 → 用户等了 187 秒回答"允许"， 结果 sh: 1: sudo: not found。而 $HOME 在"一律拒"里 → echo $HOME 被硬拒两次。

5.4 依赖缓存卷：数据每轮重置、依赖跨轮复用

- type: volume
  source: "sf-<项目>-<指纹>-home"      # 挂到 /specflow-home，HOME 也指向它
  target: "/specflow-home"
volumes:
  "sf-…": { external: true }          # ← 关键：不属于这次 up/down 的生命周期
external: true 让 down -v 不删它（~/.m2 跨轮复用）， 而项目树每轮仍是新副本。不这么做的代价是实测过的：每轮重下依赖，7 轮 sleep 240、17 分钟白等。

5.5 上下文压缩

见 §4.4 的 Compact。触发：合计字符 > 6 万；形状：system + 锚点 + 任务书 + 说明 + 尾巴 8 条。

5.6 打转检测（分级）

same = 连续相同调用的次数
if (same >= 6) → 判死："…该收场了：把这条用例标 ERROR…"
if (same >= 4) → 提醒："…这是原地打转。换一种做法…（再 2 次就收场）"
为什么是两级：OpenHands 是 3 次提醒、4 次判死； 那份研究里有句话很扎：我们原来是在最有救的那一刻把用例判死。

5.7 运行级断点

Checkpoint(node, runId, at, next, doneCases, roundsUsed, status)
写：每写回一条用例结论落一次 + 开工时 RUNNING + 预检失败 BLOCKED + 整轮失败留断点 + 全绿清掉
恢复：POST /api/node/test/resume —— 不做魔法（已到终态的本来就不会重验），只是把话说清
不存对话历史：两万字符一条的工具结果存下来就是第二份真相，恢复时还要处理 "模型看到的历史和我认为的历史不一致"。断点只说三件事：哪几条硬了、下一步干什么、花了几轮。 参考 LangGraph 的 durability="exit"：一步做完才落一次

5.8 位置提示

messages.add(user(结果正文 + "\n（当前位置：" + containerRoot + "）"))
实测模型在容器路径（/work）与相对路径之间猜，白烧 5 轮。解释一次不如每条报一次。 参考 SWE-agent：每条 observation 都钉 (Current directory: …)

5.9 崩溃恢复

Journal.sweep():  有 BEGIN 没有 END 的运行 = 被杀过 → 补记 END 成 INTERRUPTED，并如实报出来
接线点：Session.open() 每次打开项目都跑一遍（v3 之前这个方法没有调用点——文档说了、代码没做到）

5.10 收场如实

  • ⑤ 撞整轮上限也如实报已写下几条结论（原来是恒报 0）。
  • 有 SKIPPED 时不说"验完了"，而说"有 N 条被跳过（预算用尽）"。
  • 超时与失败分开说：命令超时不是"命令失败"，是"它没跑完"。

第 8 部分

怎么跑、怎么修

8.1 三个入口

双击它干什么
start.bat找 Java 17+ / 缺 jar 就编 / 看 Docker / 挑空端口 / 找密钥 / 起引擎 / 等健康 / 开浏览器
stop.bat停引擎 + 按项目名收容器与卷；-Purge 连流程数据一起删
dev.bat改前端时才用（引擎 + Vite 热更新）

不开界面的命令：java -jar target/specflow.jar env prepare|init|reset|status|down [-p 项目]。

8.2 出问题先看哪儿

症状先看这里
界面点不动某一格那一格的 blockedReason（就是 409 正文）→ 再看 docs/API.md 对应接口
某一段跑得奇怪events.jsonl（id 就是行号）→ 按 run=r-… 过滤 engine.log
想看模型到底收到什么POST /api/actuator/loggers/com.specflow {"configuredLevel":"debug"} 再跑一遍
容器起不来 / 构建不过env/<时间戳>/compose.log（原始输出全文）+ env.yaml 的 image/init
测试卡住GET /api/node/test/checkpoint 看断点；approvals 看是不是在等人
崩溃/被杀过runs/<runId>.jsonl 里 BEGIN 没有 END；打开项目时事件流会有"被中断"的 warn

8.3 两条排查用的小命令

Get-Content $env:USERPROFILE\.specflow\logs\engine.log -Tail 40          # 最近发生了什么
docker ps --filter name=sf- --format '{{.Names}}\t{{.Status}}'          # 我这套起了哪些容器

判据永远在三处：docs/ARCHITECTURE.md（契约）、docs/API.md（接口）、 docs/DELIVERY.md（验过什么 / 没做什么）。这一本解释的是为什么长这样。
