specflow · 系统说明书

给它项目和一段需求，它按五个节点把活干完：环境、上下文、用例、开发、测试。每一步交出的东西是下一步的输入，交不够就不许往下走。

这份说明书画成一张表：横向三页讲共性，纵向五页讲每个节点，最后三页源码。每页只讲一件事，页尾有「下一页」，按顺序读就不用记目录。

横向：五个节点共用的东西

全局 1 · 一次点击的骨架判 → 登记 → 干活 → 收场
全局 2 · 共用的八件东西事件流 / 闸 / 动作表 / 运行 / 叫停 / 预算 / 快照 / 错误口径
全局 3 · 环模型怎么动手：回合、工具调用、三层装箱

纵向：五个节点，一页一个

① 环境探测 → 起容器 → 在容器里真构建一次
② 上下文交四样产物，其中 changes 是 ④ 的写白名单
③ 用例清单要能逐条判“过没过”
④ 开发白名单内改真代码，每次交差编译一次
⑤ 测试副本 + 容器里逐条验，结论与证据写回清单

再往下：源码与查表

源码 1 · 闸、冻结、收场
源码 2 · 回合、压缩、补问
源码 3 · append、原子写、截断
查表 · 铁律、十二条不变式、边界、踩过的坑

三条提醒

  1. 五个节点页是同一个模板：点一下按钮 → 调用哪个类哪个方法 → 交什么 → 闸问什么 → 常见失败。
  2. 数字都能数（几个类、几条路由、几条测试）。对不上说明文档旧了。
  3. 文档里的代码是从 src/main/java 抄的；和代码不一致时以代码为准，然后回来改文档。

怎么跑起来、怎么配看仓库根的 README.md；加一个按钮要动哪几处看 CONTRIBUTING.md。
