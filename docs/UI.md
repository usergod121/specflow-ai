# specflow v3 · 界面

> 界面只有**七个页面**：欢迎页 + 工作台 + 五节点。没有多标签、没有抽屉、没有第二层导航。
> 「UI → API」的顺序：先定界面要什么，后端照着这个表提供——**界面不许自己算闸、不许自己拼状态**。

## 1. 一屏的形状

```
┌ 顶栏 ─────────────────────────────────────────────────────────┐
│ specflow   <项目名>                        [模型] [收起侧栏]   │
├ 侧栏 ─┬ 主区 ─────────────────────────────────────────────────┤
│ ① 环境 │  ① 环境搭建                        [探测环境] [起环境] ⋯│
│ ② 探针 │  ● 待完成                                            │
│ ③ 用例 │  ───────────────────────────────────────────────────  │
│ ④ 开发 │  环境声明                                    [保存]    │
│ ⑤ 测试 │  ┌ env.yaml ────────────────────────────────────────┐ │
│       │  │ image: eclipse-temurin:17                        │ │
│ 工作台 │  └──────────────────────────────────────────────────┘ │
│       │  ┌ 编译命令 ────────────────────────────────────────┐ │
│       │  └──────────────────────────────────────────────────┘ │
│       │  ▸ 工具调用 · 正在跑                                   │
│       │  ▸ 输出 · 2 份                                        │
│       │  ▸ 留档 · 30 行                                        │
└───────┴───────────────────────────────────────────────────────┘
```

**一屏只有一件事**：主区放这一格要做的那件事；其余全部收进一行一行的折叠。

## 2. 十条界面规矩（每条都是被骂过的）

1. **一页最多两个按钮**（页头：1 主 + 1 次），其余进「⋯」。
   **同一个动作只许有一个入口**——页头有了，折里不许再放一枚。
2. **状态只有一行，≤6 个汉字**：`未开始 / 待完成 / 进行中 / 已完成 / 失败 / 未保存`。
   `待完成` 对应后端的 `READY`（"轮到了、等你点"，**不是**"已经好了"——说成「已就绪」时，
   ① 上会被读成"环境已经起好了"，而用户还得去点「起环境」，这一条是用户真踩过的）。
   长解释进 `title`（悬停才出现），正文一个字都不留。
3. **每一步都有自己的徽章**（绿=成功 / 红=失败 / 灰=没跑过 / 蓝=在跑）。
   徽章读**后端落档的事实**（`facts`），不读"历史里出现过 error"——成功之后不许还说失败。
4. **归档日志最新在最上面**（`?from=` 拉到的列表倒序渲染）。"更早 N 行"往回翻。
   这份流是只追加的，最新在底部意味着每次都要滚到底——而底下还在长。
5. **工具调用是 chip 流**：默认**只画当前那一枚**（跑着的转圈，跑完换成下一条）。
   上面一行写「一共 N 次 · M 报错」，点「更早」翻历史。参数原文与结果全文在展开区里。
6. **空状态只给一句**：`还没跑` / `还没需求` / `还没用例`。怎么开始的话进 `title`。
7. **错误就地显示**：贴在触发它的那个按钮下面（红字 + 原文 + 重试），同时进归档。
   不许只弹一个 toast 就没了——失败信息必须留在页面上、可复制。
8. **对比度与命中区**：正文 ≥16px，命中区 ≥44×44px，`:focus-visible` 2px 环。
9. **不引组件库**：按钮、输入框、折叠、弹窗、chip 全是手写 CSS（变量在 `styles/tokens.css`）。
10. **动效只在 150~250ms**，且 `prefers-reduced-motion` 时全关。

## 3. 七个页面各自要什么

| 页面 | 主区（这一格要做的事） | 页头动作 | ⋯ |
|---|---|---|---|
| 欢迎页 | 挑项目：最近列表 + 手输路径 + 选文件夹 | 打开 | — |
| 工作台 | 当前流程五格速览 + 最近项目 | 新开流程 | — |
| ① 环境 | env.yaml 与编译命令两个框 | 探测环境 / 起环境 | 编译、清空输出 |
| ② 探针 | 需求（必填）+ 设计（可选）两个框 → 产物四样：要读的 / 要改的 / 上下文 / prompt（四栏都可手改） | 跑探针 / 冻结 | 保存产物 |
| ③ 用例 | 用例表（增删改，带标签与状态） | 生成用例 / 冻结 | — |
| ④ 开发 | 白名单 + 先读的 + 上下文 + prompt + 上一轮反馈（全只读，给人核「② 交代的东西真的进 ④ 了」） | 跑开发 / 冻结 | 回滚改动 |
| ⑤ 测试 | 用例表（带结论与证据）+ 总结框 | 跑测试 / 提交 | 接受并完成、再优化一轮 |

**五个节点页共用同一个骨架**（`NodeShell`）：页头 + 状态一行 + 主区 + 折叠。
骨架不许各页各写一份。

## 4. 状态从哪来（界面一个字都不许自己推）

| 界面上的东西 | 唯一来源 |
|---|---|
| 节点三态、能不能点 | `GET /api/flow` 的 `state` / `blockedReason` |
| 步骤徽章（成功/失败） | `GET /api/flow` 的 `facts`（`envReady` / `compilePassed`…） |
| 进度、工具调用、失败原文 | `GET /api/node/<key>/events?from=` |
| 那一页的结论（花了多久、几条、下一步） | 事件流里最后那条 `type=result` 的 `payload` |
| 待回答的高危命令 | `GET /api/node/test/approvals` |

## 5. 文案预算（机器钉住）

`tests/unit/text.spec.js` 会逐句数**汉字**：

- 状态条 ≤6 字；按钮 ≤4 字；折叠标题 ≤4 字；空状态正文 ≤6 字；
- 界面上**不许出现**："点击这里"、"您可以"、"请注意"、"温馨提示"、以及任何超过 6 字的解释句；
- 长解释一律进 `title`（悬停可见），正文只留结论。

## 6. 目录结构

```
src/main/frontend/src/
  main.js  App.vue  router.js  store.js  api.js      # api.js：唯一发请求的地方
  styles/tokens.css   # 颜色/间距/字级：唯一一处定义
  styles/app.css      # 布局与组件样式（手写，不引库）
  components/  NodeShell.vue  Fold.vue  Chip.vue  Chips.vue  Badge.vue
               Empty.vue  Fail.vue  MoreMenu.vue
  views/       Welcome.vue  Workbench.vue  EnvNode.vue  ProbeNode.vue
               CasesNode.vue  DevNode.vue  TestNode.vue
  lib/         events.js（事件→行/chip）  facts.js（facts→徽章）
               text.js（文案裁剪）  actions.js（按后端声明的 id 绑处理函数）
               flow.js  pages.js（五格的名字与顺序）
```

`lib/` 里的东西**纯函数、被单测钉住**；`.vue` 只做渲染与调用。

**按钮文案不在 `.vue` 里**：名字/顺序/主次/进不进「⋯」全由后端 `flow/Actions.java` 声明，
视图只写 `const handlers = { run, freeze, rollback }` 再 `head(node, handlers)`。
视图里出现 `label:` / `tip:` 会被 `wiring.spec.js` 判红——这是"同一个动作只许有一个入口"
那条规矩的机器版本。
