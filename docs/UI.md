# specflow · 界面（第三版）

> 界面只有**七个页面**：欢迎页 + 工作台 + 五节点。没有多标签、没有抽屉、没有第二层导航。
> 「UI → API」的顺序：先定界面要什么，后端照着提供——**界面不许自己算闸、不许自己拼状态**。
> 视觉细则（颜色/字号/间距/动效/禁项）在根目录 `DESIGN.md`；这一份是**结构契约**。

## 1. 目录（现在的样子）

```
src/main/frontend/
  index.html                 内联图标（不发 /favicon.ico 请求）
  vite.config.js             outDir=dist；dev 把 /api 代理到 SPECFLOW_PORT||8780
  src/main.js                createApp + router + 两份样式
  src/App.vue                外壳：左栏五格流水 + 右栏页面 + toast
  src/router.js              七条路由（history 模式，后端有 SPA 回落）
  src/api.js                 唯一发请求的地方（全部 40 条路由 + ApiError）
  src/store.js               唯一的状态与唯一的刷新口（见 §4）
  src/styles/tokens.css      颜色/字级/间距/动效：唯一一处定义
  src/styles/app.css         布局与组件样式（手写，不引组件库）
  src/lib/status.js          状态 → 人话（未开始/待完成/进行中/已完成/失败）
  src/lib/format.js          秒、时钟、行数组↔多行文本、摘要
  src/lib/useNode.js         进哪一格就设「当前格」+ 接事件流
  src/components/PageHead.vue    页头：标题 + 状态 + 动作条 + 闸 + 失败条
  src/components/EventStream.vue 事件流（最新在上、工具 chip、看原文）
  src/views/{Welcome,Workbench,EnvPage,ProbePage,CasesPage,DevPage,TestPage}.vue
  tests/unit/logic.spec.js   纯函数 + store 刷新纪律（11 条）
  tests/smoke.mjs            真浏览器冒烟（七页 + 按钮对账 + 点击发请求 + 换项目）
```

```
┌ 左栏 216px ─┬ 右栏（≤1180px）──────────────────────────────────┐
│ specflow v3 │  环境搭建            ● 待完成    [探测环境][起环境] ⋯│
│             │  ! 环境还没起来：点「起环境」跑一次…                │
│ ①环境  ●    │  ────────────────────────────────────────────────│
│ ②探针       │  环境声明                              [保存]      │
│ ③用例       │  ┌ env.yaml ─────────────────────────────────┐   │
│ ④开发       │  └──────────────────────────────────────────┘   │
│ ⑤测试       │  编译命令                                             │
│ ·工作台      │  [mvn -q -DskipTests compile            ]          │
│             │  ▸ 留档                                            │
│ 项目名      │  ┌ 事件流（最新在最上面）──────────────────────┐  │

```

- **一屏只有一件事**：主区放这一格要做的那件事；过程与留档收进折叠。
- 状态永远只有一枚 pill；闸那句话紧跟在页头下面，**原样**显示后端的话。

## 3. 页面各自要什么

| 页面 | 主区 | 页头动作（后端声明） | 「⋯」 |
|---|---|---|---|
| 欢迎页 | 最近项目（每行一个按钮）+ 路径输入 | — | — |
| 工作台 | 五格一览（状态 / 为什么不能往下 / 去处理）+ 所有流程 | 新开流程 | — |
| ① 环境 | env.yaml 与编译命令两个框 + 输出 | 探测环境 / 起环境 | 编译、清空输出、改超时、跳过这步、冻结、叫停 |
| ② 探针 | 需求 + 设计 → 四栏产物（都可手改） | 跑探针 / 冻结 | 存需求、保存产物、叫停 |
| ③ 用例 | 用例表（增删改，带标签与状态） | 保存 | 生成用例、冻结、叫停 |
| ④ 开发 | 白名单 / 先读的 / 上下文 / prompt / 上一轮反馈（全只读） | 跑开发 / 冻结 | 回滚改动、叫停 |
| ⑤ 测试 | 清单结论 + 审批 + 总结 + 断点 | 跑测试 / 提交 | 接受并完成、再优化一轮、从断点续跑、冻结、叫停 |

## 4. 状态从哪来（界面一个字都不许自己推）

`src/store.js` 的规矩，**改界面之前先读这一段**：

1. **唯一刷新口**：`refresh()` 读 `GET /api/flow`，把 `flow / running / stage` 一起更新。
2. **任何动作之后都刷新**：所有动作走 `act(key, work)`，它在成功之后、以及 409 之后都会 `await refresh()`。
   所以"改了没反应"和"状态发霉"这两类 bug 从结构上不可能发生。
3. **换项目 = 全量重来**：`openProject()` 清 flow / 事件 / 游标 / 失败条，再 `refresh()`。
4. **有活在跑时 1.5 秒轮询兜底**：SSE 断了也不会出现「按钮永远灰着」。
5. **失败就地留一条**，可关；同一条不重复堆。
6. **动作按钮只按后端声明渲染**，`disabled` 每次渲染重算（禁止写成挂载时求值的字面量）；
   `onlyWhileRunning` 的那一枚（叫停）**提升到页头最前面**——它是唯一能解开死锁的退路。

## 5. 文案预算（机器钉住）

- 正文里的中文 ≤6 个汉字；长解释进 `title` / `tip`；
- 状态词只有五档：`未开始 / 待完成 / 进行中 / 已完成 / 失败`（`待完成` = 后端的 `READY`，
  **不许**叫「已就绪」——在 ① 上会被读成"环境已经起好了"）；
- 按钮 ≤4 个字；折叠标题 ≤4 个字；空状态 ≤6 个字 + 一句"从哪开始"；
- 不许出现：「点击这里」「您可以」「请注意」「温馨提示」。

## 6. 验证（怎么证明它不是"看着像做了"）

```
cd src/main/frontend
npx vitest run                     # 11 条：状态词 / 格式化 / store 刷新纪律
npx vite build                     # 产物 dist/
node tests/smoke.mjs <jar> <端口>   # 真 Chrome 走七页，对账三件事：
                                   #   ① 声明了动作就必须画出来
                                   #   ② 能点的按钮点下去必须发请求
                                   #   ③ 换项目后五格必须跟着换
```

`start.bat` 那一侧也加了两道校验：缺 `node_modules` 先 `npm install`；打完包**检查 jar 里的
`static/index.html` 与 `static/assets/*.js` 是否存在**（否则双击进去是一片白），并强制 `clean` 重打，
免得旧包混进 jar。
